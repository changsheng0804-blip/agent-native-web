# Agent Runtime Adapter — v1.1.0 蓝图版(Blueprint)

> 版本日期:2026-08-30
> 基于:v1.0.0(原 `agent-runtime-extension`)
> 定位:Agent 的 CAD 图纸 + 低成本阅读的网页视频

## 一、这个版本是什么

在原版(把网页实时翻译成 `window.agentWorld` 可查询世界)的基础上,按"CAD 图纸"思路补上了三个核心能力:

1. **编号系统(图纸的灵魂)** —— 每个元素有**无歧义的稳定编号**和**可读的语义名字**,任何 AI 拿到编号就能精准找到并操作元素
2. **图纸查询(构件表)** —— 按角色/文本/名字/坐标过滤查构件清单、查单个构件详情、看整张图的图层结构
3. **变更日志(网页视频)** —— 页面每处变化都被记录成"帧"(append-only 事件流),AI 可以像看视频一样**增量续读**,而不是每次都重新看整张图

用一句话理解:原版给 AI 一张"网页地图",这个版本让地图上的**每个建筑都有门牌号、名字、坐标**,并且**实时记录整条街的变化**。

## 二、相比原版的变化

### 新增 API(挂载在 `window.agentWorld` 上)

| API | 作用 | 类比 |
|---|---|---|
| `agentWorld.query.findEntities({role, tag, text, name, interactive, inViewport})` | 按条件过滤查构件清单(编号/名字/标签/文本/坐标/是否可交互) | CAD 构件表 |
| `agentWorld.query.getEntity(id)` | 查单个构件详情(含上下左右邻居、所在区域) | 构件图纸 |
| `agentWorld.query.layers()` | 图层视图:结构/语义/空间/交互/名字统计 | 图纸图层 |
| `agentWorld.query.resolve(名字或ID)` | 弱 ID 解析:用名字找到编号,页面变了名字失效可重新解析 | 查门牌号 |
| `agentWorld.changes(sinceSeq)` | 读取自某序号以来的变更事件(增量、带游标) | 视频帧续读 |
| `agentWorld.log(n)` | 最近 n 条变更日志 | 最近片段 |

### 编号规则变化(重要,与原版不兼容)

| | 原版 v1.0.0 | 蓝图版 v1.1.0 |
|---|---|---|
| 元素编号 | 页面自带 id(如 `7`、`18`)与计数器生成的 `el_div_5` 混用 | **统一 `el_<序号>`**(如 `el_89`),页面自带 id 降级存入 `attributes.id` |
| 稳定性 | 计数器基于标签+序号,SPA 删除重建会漂移 | WeakMap 绑定 DOM 节点,节点存活期间编号绝不改变 |
| 语义名字 | 无 | `role.短文本`,如 `combobox.round-trip`、`button.搜索`;同名自动加序号 |

### 修复的缺陷

- **SVG 崩溃**:某些 SVG 元素的 `className` 是 `SVGAnimatedString` 对象(非字符串),原版直接 `.toLowerCase()` 导致整页注入失败(Google Flights 等大量使用 SVG 的页面必现)。已修复 `engine/scanner.js`、`runtime/scanner.js`、`all-in-one.js` 三处。
- 容器元素(html/body)名字污染:固定命名 `root.html` / `root.body`。

### 补充改进(2026-08-31)

- **input/textarea 的 value 入图**:`getElement/getEntity` 的 `attributes.value` 实时返回输入框当前值(fill 后无需重新扫描即可验证表单状态)
- 构建脚本路径修复:`scripts/build_all_in_one.py` 现在基于自身位置定位项目根(可被复制到任何目录独立构建)
- **观察器饿死修复(2026-08-31,实战驱动)**:原 `content/observer.js` 用"每次 mutation 重置 150ms 防抖",持续变更页面(懒加载/轮播/广告刷新,如 Booking.com)会让 `onChange` 永远不触发 → 世界模型停更。实测 Booking 上 world 停滞在 678 个、`forceRefresh` 却抓到 2426 个。改为**累积式防抖 + maxWait(1000ms)兜底**:mutation 累积到 pending,变更停止 150ms 后处理;若持续变更导致防抖被不断重置,最多 1000ms 强制 flush 一次。修复后 Booking 捕获率 28% → 98%。改后需重新构建 `all-in-one.js`。

## 三、验证结果(实测)

### 本地动态页(每 300ms 自动插入元素)

- 编号空间干净:全部 `el_<seq>`,无裸数字 ID 混入
- 变更日志:1.5 秒读到 5 条 `add` 事件(item-5..9),游标续读不重不漏
- 名字可读:`heading.动态测试页`、`button.搜索`、`input.搜索`

## 四、怎么用

### 方式一:手动注入(推荐给 Agent 场景)

把 `all-in-one.js` 通过浏览器的 `addInitScript` 注入(Playwright 等),每次导航自动生效:

```javascript
// Playwright 示例
page.add_init_script(读取 all-in-one.js 内容);
// 之后任何时刻:
page.evaluate("agentWorld.query.findEntities({ role: 'combobox' })");
page.evaluate("agentWorld.changes(0)");  // 看页面变化
```

### 方式二:Chrome 扩展

1. 打开 `chrome://extensions/`
2. 开启「开发者模式」
3. 「加载已解压的扩展程序」→ 选择本目录
4. 之后在任意网页控制台使用 `agentWorld.*`

### 方式三:Tampermonkey / Violentmonkey

将 `all-in-one.js` 内容粘贴为用户脚本(`@match <all_urls>`,`@grant none`,`@run-at document_idle`)。

## 七、技术附录:变更日志事件格式

```json
{ "seq": 6, "t": 1720000000000, "type": "add", "id": "el_11", "name": "content.item-5" }
```

- `type`: `add`(新增) / `remove`(删除) / `update`(属性变化) / `visibility`(滚动视口) / `init`(世界建立)
- `seq`:全局递增序号,`changes(sinceSeq)` 用它做游标
- 环形缓冲保留最近 2000 条,超出自动丢弃最旧
