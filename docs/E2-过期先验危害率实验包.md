# E2 实验包：过期先验危害率（暂停待跑，其他分支智能体可直接执行）

> 状态：PAUSED。起跑条件：有多智能体 harness（同模型多子代理、隔离 MCP 进程与浏览器上下文）。
> 目标：量化回答——**过期地形先验的误导率是否收敛**。不收敛，地图共享免谈（见探索方向文档 §1 解封条件）。
> 前例：旧验证 GitHub G1（B组52s vs A组48s + Issues入口误导）即本实验要复刻并放大的现象。

## 1. 三臂设计（比旧验证多一臂）

| 臂 | 先验 | 测什么 |
|---|---|---|
| A（对照） | 无地形卡，纯现场理解 | 基线 |
| B（正确先验） | 有效地形卡（§3 卡片B） | 增益上限 |
| C（过期先验） | 过期/错误地形卡（§3 卡片C） | **危害率（核心指标）** |

## 2. 控制（照抄旧验证#二，不许偷工）

- 同模型同推理强度子代理，每代理只负责一臂一站，站内完成全部任务。
- 每任务独立 MCP 进程 + 全新浏览器上下文；无登录、无写入、只读。
- `world_map` 三臂均可用（验证的是外部先验增益，不是地图工具有无）。
- 每臂每站每任务 ≥3 次独立重复。

## 3. 地形卡模板（以 GitHub 仓库页为例，可换站复用句式）

**卡片B（正确，先验有效）：**

```text
本站是代码仓库页。顶部导航组织代码与协作功能；
问题列表在 Issues 页内，不在首页首屏；发布信息在 Releases/Tags 区。
先读实时页面确认入口是否存在，再行动。
```

**卡片C（过期，复刻 G1 教训，故意写错一条）：**

```text
本站是代码仓库页。顶部导航有 Code、Issues、Pull requests 等入口，
Issues 入口就在首页顶部导航中。直接去点它。
```

C 卡只有“Issues 在首页顶部”这一条是错的（实际渲染常不暴露），其余全对——测的就是**单条过期先验的毒性**。

## 4. 任务电池（只读、可验证）

1. 在仓库首页找到 Code / Issues / Pull requests / Actions / Releases 入口，判断所属区域。
2. 进入 Issues 页，定位筛选/搜索控件所在区域，读出第一个公开问题标题与状态，返回确认路径。

## 5. 记录表（每轮一行，#七八项全收）

```text
臂/站/任务/重复序号 | 首次定位时间 | 首次操作时间 | 总时间 |
MCP调用数 | 工具分布 | 返回字符数 |
零命中次数 | ambiguous次数 | 先验冲突次数(先验说有、页面说无) |
错误操作次数 | 恢复时间 | 终判正确? | 主标签分布 |
```

## 6. 判定线

- **危害率** = C臂终判错误率 − A臂终判错误率。>0 即先验有毒。
- **解封地图共享当且仅当**：B臂在两站同时降总时间或错误恢复成本，**且** C臂危害率 ≈0（有实时事实优先机制兜住，错先验带不偏）。
- 否则：地图共享无限期封存，回头加固实时校验。
