这里的指标是“流程资产是否能够沉淀和复用”的第一版基线，不是普通页面 Agent 与任务图 Agent 的速度或模型费用对照。当前实现的直接浏览器动作数量尚未因为任务图自动减少；已经验证的收益主要是可规划、可阻断、可审计和可复用，下一阶段再测时间、调用量和错误率。

## 真实运行中发现的问题

### 1. URL 形态不是固定模板

GitHub 提交筛选条件后，实际路径可能出现筛选片段，不能只用固定 `/pulls` 判断业务状态。适配器改为使用路径前缀和结果探针组合判断。

### 2. 页面级状态会受无关动态元素影响

不同会话中的输入框数量和页面细节不完全一致，导致完整页面状态编号不同。规划和回放在业务状态已明确时允许使用业务状态作为兼容锚点，同时保留精确状态匹配优先级。

### 3. 动作后果与最终业务状态可能不同步

筛选提交动作有时返回 `uncertain`（结果不确定）或 `unchanged`（页面整体无明显变化），但随后业务探针可以确认结果状态。系统保留动作原始后果，不把它强行改写成成功。

## 尚未达到的级别

本次图合并结果是 `replayed`，不是 `verified`。原因是部分迁移边的独立回放次数或预期分支覆盖仍不足。真实站点一次通过只能证明“这次路径可复现”，不能证明网站完整业务逻辑已经恢复。
