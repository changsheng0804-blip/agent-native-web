# 三问实验:缺失的外部事实,能否靠「仔细想想」救回来?

> 日期:2026-09-08 · 模型:kimi-k2.7-code · 每组 3 次,共 18 次运行
> 脚本:`mcp/experiments/three_questions.py` · 原始数据:`mcp/experiments/three_questions_results.jsonl`
> 复现:`export KIMI_API_KEY=... && python mcp/experiments/three_questions.py`

## 问的问题

项目护城河的核心假设是:**存在一类事实,它不在任何观察里,所以任何纯推理的 agent 都无法可靠得到它。**

如果这个假设成立,护城河是逻辑上的。如果不成立,方向就该收。

三个可能推翻它的质疑,按成本从低到高:

| # | 质疑 | 如果成立 |
|---|---|---|
| ① | 这个事实在观察里其实存在 | 不是护城河,是编码问题 |
| ② | 强模型能推出来 | 会被 scaling 吃掉 |
| ③ | **加一句提示就能救** | **那是 prompt,不是 Runtime** |

第 ③ 问最便宜也最致命,所以这次专门做了对照组。

## 设计

两个场景,每个三组。**真相与「保守默认答案」相反**——模型只要乱猜就必错。

| 场景 | 页面显示 | 真相(需外部事实) |
|---|---|---|
| **ledger** | 可用余额 `¥100` | 权威账本是 **¥0** |
| **async** | 「✅ 已提交,排队中」 | 3 秒后后台任务**失败** |

| 组 | 设置 |
|---|---|
| **N 无事实** | 只有动作窗口内的观察(模型默认处境) |
| **F 有事实** | 额外注入缺失的那条事实(权威账本 / 异步结果) |
| **C 提示组** | 同 N,系统提示加「请谨慎判断,不确定就说不确定,不要假设成功」 |

三组都用完整后果卡(`AGENT_WORLD_VERDICT_MODE=full`),**唯一变量是提示与事实**。

## 结果

| 场景 | N 无事实 | F 有事实 | C 提示组 |
|---|---|---|---|
| ledger | **0%** | **100%** | **0%** |
| async | **33%** | **100%** | **0%** |
| **总体** | **17%** | **100%** | **0%** |

错误类型分布:

```text
ledger  N: {uncertain: 1, other: 2}      ← 答不出,或答非所问
ledger  F: {correct: 3}                  ← 给了账本就全对
ledger  C: {uncertain: 2, other: 1}      ← 提示让它诚实,但依然不知道

async   N: {wrong: 1, other: 1, correct: 1}   ← 会猜「成功」(错)
async   F: {correct: 3}
async   C: {uncertain: 3}                ← 提示让它不敢猜,但依然不知道
```

## 结论

【已确认】**第 ③ 问的答案是「救不了」——而且比预期更干净。**

提示组(C)正确率 **0%**,和无事实组(N)的 17% 没有实质差别,**远低于**有事实组(F)的 100%。

提示确实改变了行为:模型不再乱猜(ledger 的 C 组从"答非所问"变成"不确定";async 的 C 组从"猜成功"变成"不确定")。**但它只让模型变诚实,没让它变正确。** 「不确定」在工程上等于没答案。

【已确认】**第 ② 问的答案是「推不出来」。** 在没有任何外部事实时,模型对这两类问题都无法可靠回答。

【推断】**护城河在逻辑上成立,但价值形态需要重新表述。**

原文档写的是"防止模型把没生效当成功"。数据不支持这个说法——提示就能让它不乱猜。
数据支持的是:**提示能让模型知道"我不知道",只有事实能让它知道答案。**

这两句话对产品的含义完全不同:
- 前者卖的是"防止错误",值钱程度取决于模型的鲁莽程度(会随模型变好而下降);
- 后者卖的是"提供答案",值钱程度取决于事实是否可得(不随模型变好而下降)。

## 诚实的边界

| 限制 | 说明 |
|---|---|
| 样本小 | 每组 3 次,共 18 次;18 次里 C 组 6 次全部答不出,信号一致但样本仍小 |
| 单模型 | 只有 kimi-k2.7-code;换更强的模型 C 组可能变好(但那正是要测的 P2) |
| 单任务形态 | 两个场景都是"页面显示 vs 后端真相"的对抗,可能低估了其他形态 |
| **实验过程中我修正了三处自己的设计缺陷** | 见下 |

## 修正记录(自我审计)

第一版结果出来后,发现三处设计缺陷,修正后重跑:

1. **判分被污染**:ledger 页面上有个"冻结金额 ¥0",我原来的判分 `"¥0" in text` 把
   dump DOM 的输出也算成答对。→ 改为**要求明确回答余额值**,并区分 correct/wrong/uncertain。
2. **真相与保守默认重合**:原来 causal 场景真相是"否"、async 真相是"未完成",
   模型只要**默认否定**就蒙对,测不出事实的价值。→ 改成**真相与保守猜测相反**
   (显示 ¥100 而真相 ¥0;显示已提交而真相失败)。
3. **工具替模型答了**:async 场景原夹具里工具自己判 `unchanged`,等于变相提示"没成功"。
   → 改夹具让动作**确实生效**(页面出现明显变化),工具判 `progressed`,
   但**任务最终结果**仍不可知。这才真正测到"结果不在观察里"。

**这三处都是"让实验看起来更支持我"的反方向修正。** 记在这里以便复核。

## 对方向的含义

1. **第 ③ 问已答,可以往下走**:提示替代不了事实。
2. **但价值主张要改写**:从"防止假成功"改成"提供不可推理的事实"。
   → 已同步到[核心命题](核心命题-反馈闭环是第一杠杆.md)。
3. **下一步该测 P2**(增益随模型变强是否衰减):C 组在当前模型上 0%,
   若换强模型后 C 组仍然答不出,则这一层不会被 scaling 吃掉——**那才是护城河成立的最终证据**。
4. **顺带发现一个真实缺陷**:async 夹具里点击**确实生效了**(状态文本变了),
   但工具报 `unchanged`——纯文本更新类效果检测不到(已知 FN,已在
   `test_assumption_e_glass.py` 里锁定为回归基线)。
