## 问题清单

### P1（建议合入前修）

**effect 字段可能整体缺失，违反 §2 必填**
- `_wait_click_effect` 在 `snap_before` 为空时直接 `return None`（[server.py:2564](mcp/server.py#L2564)），而 click/fill/click_at 三处挂载都是 `if effect: ret["effect"] = effect`（[server.py:2835](mcp/server.py#L2835)、[2865](mcp/server.py#L2865)、[2915](mcp/server.py#L2915)）。
- 即构件快照失败/SPA 重建竞态时，卡片**整个缺 `effect.*`**（verdict/observed/evidence 都没有），与规格"少一个即不合格"冲突。当前夹具未触发此路径，但 R2 字段齐全性检查必挂。
- 建议：`_outcome_card`（[server.py:2027](mcp/server.py#L2027)）内兜底——`ret` 无 `effect` 时补 `{"verdict": "no-change", "observed": [], "why": "证据基线缺失"}`，或调用方无条件挂载。

### P2（建议合入前修或 R2 前排期）

1. **`page.anomaly` 恒 False、`next.candidates` 恒 `[]`**（[server.py:2162](mcp/server.py#L2162)、[2165](mcp/server.py#L2165)）：规格 §2 声明了字段但实现从不填充。anomaly 应接上状态卡已有的异常检测，别硬编码。
2. **errored 卡 `sources={}`、`effect={}` 空壳**（[server.py:2218](mcp/server.py#L2218)）：键在、内容空。规格说"缺失即不合格"，空对象语义上等于 0 个字段被标记；R2 若逐卡检查 sources 非空会挂。至少 `effect` 应带 `{"verdict": "unknown"}` 之类的显式无判定表达。

### P3（留待 R2/R3）

1. **直接调用 `world_batch_fill` 时子卡序号共享**（[server.py:2969](mcp/server.py#L2969)）：每字段内部 `_t_world_fill` 各 mint 一张 `evidence_seq = w+1` 的同号卡（被丢弃），失败字段不 mint 卡，批次卡同样取 w+1——对外对账不受影响（只有批次卡存活），但与 world_act steps 路径（每步独立序号）语义不对称；证据日志只记 1 条 batch 条目。若 R3 按步骤对账会踩。
2. **测试缺口**：uncertain 态（batch_fill 部分成功→uncertain）无断言；occluded 态（Phase 3 归因）无断言；errored 卡只查结构不查 §2 字段（`assert_receipt` 没跑在 errored 卡上）；`world_outcome(since)` 跨卡连续性（读旧卡→再动作→再读）未测；verbose 全量 status 分支未测。
3. 性能注记：`_challenge_detection` 每次疑似提交动作后全页 `querySelectorAll('*')`+getComputedStyle，万级元素页面每次提交动作增加数百 ms——只发生在提交类动作，可接受，可优化。
