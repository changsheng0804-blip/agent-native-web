# 落地路径：从命题到可验证资产

> **状态**：路线图（可执行）。依据 [核心命题-反馈闭环是第一杠杆](核心命题-反馈闭环是第一杠杆.md)。
> **原则**：每条路径必须给出**验收判据**。没有判据的条目不许写成规格，只能进实验目录。

---

## 0. 总览：三条主线

```text
主线 A｜把已确认的洞补上        ← 现在，1-2 天，无依赖
主线 B｜把卡变成可嵌入的 Runtime ← 2-4 周，A 完成后启动
主线 C｜用外部基准把「自证」变「被信」 ← 与 B 并行，4-8 周

被砍线｜感知层扩展（编号/导览/地图/地形）、任务图、地图公地、业务运行时 —— 冻结
```

三条线的共同目标只有一个：**让 Runtime 成为可被第三方使用和验证的资产**，而不是项目内部的自证。

**定位口径（2026-09-08 修正）**：

```text
感知层            → 可替换的传感器（sensor），不做护城河
证据/因果/验证/信任/恢复 → 核心 Runtime，长期价值所在
```

> 注意：验证层内部仍要再切一刀——「从已有观察做更准判断」的部分会被模型能力吃掉；
> 只有「缺失的外部证据 / 权威状态 / 因果关系 / 来源身份」不可能靠模型 scaling 解决。
> 详见核心命题 §2.2。**所以 B 线要造的是 Runtime，不是更好的判读器。**

## 主线 B：把卡变成 Runtime（2-4 周）

### B1. 抽独立包：`act_verify`

现在卡嵌在 MCP 返回值里，只有本项目的 `SKILL.md` 消费它。抽成不依赖 40 个工具的独立 Runtime：

```text
输入：传感器信号（DOM/截图/a11y/网络/控制台/外部权威）+ 动作窗口
输出：{ page_outcome, situation, effect, sources, evidence_seq, changes_seq }
职责：证据 / 权威状态 / 因果 / 来源身份 / 恢复（见核心命题 §7）
附：JSON Schema + 纯函数 API + 无 Playwright 依赖的判定核心
```

**关键设计要求：传感器可插拔。** 当某个传感器（比如更强的截图判读）变强时，Runtime 应把它当输入源接进来，而不是当竞争对手。判定核心不应硬编码依赖某一种传感器。

**为什么这是关键一步**：能被别人插在别人的 agent 上，才叫组件；只能自己用，叫内部约定。

**验收判据**：写一个 30 行的示例，把 `act_verify` 接到 **Playwright MCP** 或 **browser-use** 上并跑通一次真实动作。

### B2. 假成功代价最小对照演示（1 天，成本最低、说服力最高）

构造一个页面：点击后 DOM 无任何变化，但实际已提交（或反之）。分别用 Playwright MCP 的 a11y 树和本项目的卡走一遍，把日志并排贴出来。

**这是唯一能让人秒懂的东西**，优先于任何文档。

### B3. 失败注入测试套件（fault injection）

刻意注入静默失败，测**「agent + harness」整体**是否检测得到：

```text
注入类型（与核心命题 §2.2 五反例一一对应）：
  ① 显示成功但后端 422
  ② 按钮变灰但请求 rollback
  ③ POST 202 后异步失败
  ④ DOM 值 ≠ 权威账本值
  ⑤ 页面变化非本动作引起（websocket 刷新）
  另加：无副作用点击 / 全屏遮罩拦截 / 受控组件值重置 / 后台轮询 2xx 干扰
指标：假成功率（claimed_success ∧ ¬verified_success）
```

**为什么值钱**：它把「卡好不好」变成「卡让 agent 少错多少次」，而且可复现、可对比、不依赖特定模型。
**同时它定义了 Runtime 的边界**：每条注入对应一类缺失事实，能检出即证明对应职责已落地。

### B4. 权威状态接入点（Runtime 的第四类职责）

前四类职责里，「权威状态」目前完全空白——DOM 说什么就是什么。需要设计一个受控的外部真值接入点：

```text
形态候选：站点适配器声明 / 后端接口校验 / 账本查询 / 人工确认
要求：只在显式配置时启用，不自动推断后端逻辑
```

**验收判据**：能对一个「DOM 显示 $100 但账本 $0」的场景给出 `unchanged` 或 `uncertain`，而不是 `progressed`。

### B5. 卡的瘦身与可读性

卡当前字段多，弱模型只读 `page_outcome`。补一个「一行卡」模式给弱模型，全字段卡留给审计。

## 主线 C：外部基准（4-8 周，与 B 并行）

### C1. 验证层开 / 关的对照实验（**修正 issue #16 的轴**）

`mcp/experiments/astra_canvas_phase1/` 现在测的是「结构化接口 vs 视觉」——那是**感知维度**，正好是被模型能力吃掉的一半，而且用最强模型测，等于主动选会输的战场。

**应该测**：

```text
同一模型 × 同一任务集 × 验证层开/关
任务集分层（必须分层，不能笼统测「验证」）：
  A 组「可判断」：成功信号在观察里可见（截图写着 Success）→ 预期强模型不需要外部证据也能判对
  B 组「外部事实」：成功信号不在观察里（§2.2 五反例）→ 预期强模型也判不对
指标：假成功率 / 重复动作率 / 任务成功率 / 人工介入次数 / 步数 / token
```

**这是命题 P1 的直接检验**。如果两类任务增益无差异，命题不成立，应立即调整方向。

### C2. 预测 P2 的检验（最关键）

**增益随模型能力提升，在感知维度与验证层的可判断部分衰减，在外部事实部分不衰减。**

做法：同一个 Runtime，配 3 个能力档位的模型（弱/中/强），在 A 组 / B 组任务上各跑一遍。

- 若 A 组增益随模型变强衰减、B 组不衰减 → **命题成立，且给出了 Runtime 的精确边界**；
- 若 B 组增益也消失 → 说明那些「缺失事实」其实模型能推出来，战略要重写。

**这个实验结果直接决定 Runtime 值不值得做。**

### C3. 公开可复现的基准报告

第三方能按文档跑出同样结果。指标、任务、夹具、脚本全部公开。

**这是把「自证」变成「被信」的唯一路径。** 现在所有「五态合格」的证据都是自己的 harness 跑自己的站点。

## 头脑风暴：14 条可落地的想法

按「Runtime 深挖 / 对外可验证 / 场景收窄 / 生态接入」四类。每条给成本与判据。

### 类别一：Runtime 深挖（做深护城河）

**1. 把「假成功率」立成头号指标**
定义 `claimed_success`（模型自称完成）与 `verified_success`（环境裁判）的差。这是唯一能一句话说清价值的数字。
- 成本：低（Astra Canvas 实验里已有这个概念）
- 判据：能对一个任务集给出 `假成功率 = X%`，且 Runtime 开启后下降

**2. `uncertain` 升级为强制协议**
现在 `uncertain` 只是标签。改成：出现 `uncertain` 时系统**强制**要求一次复核，并把「未复核就继续」记为违规（SKILL 里已有铁律，但无强制）。
- 成本：中
- 判据：违规次数可被统计，且强模型下违规率显著低于弱模型

**3. 卡链 + 哈希链接（可审计 artifact）**
把卡按序落盘，用哈希链串联，第三方可离线验证「这张卡没被篡改、序号没跳」。
- 成本：中
- 判据：写一个 20 行的离线校验器，能检出人为篡改
- **价值**：这是「交割单」的真正形态，面向审计/合规场景

**4. 高风险动作闸门（irreversible gate）**
对不可逆动作（支付、提交、删除、授权），要求 `progressed` + `confidence=high` + 无 `uncertain` 才允许继续，否则强制停。
- 成本：中
- 判据：注入「提交成功但被误判为失败」的场景，闸门必须拦住重复提交

**5. 因果窗口最小化**
时间线用 600 事件环形缓冲，但判定只需要窗口内信号。为 `act_verify` 定义一个**最小充分信号集**，让判定不依赖全量时间线。
- 成本：中
- 判据：用最小信号集复现全部现有判定结果，零回归

**6. 异步结果追踪（对应反例 ③）**
`202 Accepted` 之后的结果不在动作窗口内。需要「动作 → 任务 ID → 后续状态」的追踪，把验证窗口延长到后台任务结束。
- 成本：高
- 判据：构造 202 → 30 秒后失败 的夹具，Runtime 必须能给出 `errored` 而不是 `progressed`

**7. 权威状态接入（对应反例 ④）**
DOM 显示值 ≠ 真实账本值。需要一个受控的外部真值接入点（站点适配器声明 / 后端接口校验 / 人工确认）。
- 成本：高（见 B4）
- 判据：「DOM $100 / 账本 $0」场景必须判 `unchanged` 或 `uncertain`

### 类别二：对外可验证（让别人能信）

**8. 30 行接入示例**
把 `act_verify` 接到 Playwright MCP / browser-use 上，跑通一次真实动作。成本极低、说服力极高。

**9. 失败注入套件（见 B3）**
把「检测静默失败」变成可跑的命令，别人能对**自己的 agent** 跑。

**10. 一份英文 README + 一段 90 秒演示**
现在 0 star、无英文、无 topics。技术上没做完之前不急着推广，但 B1 完成后必须补。

### 类别三：场景收窄（把价值放到有代价的地方）

**11. 高代价场景清单**
明确列出：支付/下单、表单一次性提交、权限授权、破坏性操作、企业 SaaS 后台配置。**宣称只在这些场景有效**，不宣称通用。

**12. 与 WebMCP 的正向对接**
探测 `document.modelContext`，有原生工具优先走工具，用本项目的 Runtime 做**执行后验证**。这正是 WebMCP Non-Goals 留下的空位，也是项目文档早已设想的「双通道」。
- 成本：中
- 判据：在一个实现了 WebMCP 的页面上，工具调用后用卡验证生效性

### 类别四：生态与工程

**13. LITE 反转为默认**
默认只暴露 6 词（10,003 字符），`AGENT_WORLD_FULL=1` 才挂 34 个调试工具。默认上下文成本 **-68%**。
- 成本：低
- 判据：默认模式下工具列表长度与文档一致

**14. 砍掉/冻结清单落地**
死 JS 2,835 行（`extension/runtime|overlay|ui|popup|content.js`，全库零引用）、任务图簇 1,697 行（A/B 无增益）、4 篇探索方向文档 934 行。
- 成本：低
- 判据：`工程治理-check.py` 加「manifest 未引用文件必须位于白名单目录」守卫

## 90 天节奏

```text
第 1 周    主线 A 全部完成（6 项，含 A6 五反例基准）+ 负向验证（门禁能红）
第 2-4 周  B1 抽 act_verify Runtime + B2 对照演示 + B3 失败注入套件
第 3-5 周  B4 权威状态接入点 + B5 卡瘦身
第 3-6 周  C1 分层对照实验（修正实验轴）+ 冻结/砍掉清单落地
第 6-10 周 C2 预测 P2 检验（三档模型 × A/B 两组任务）+ C3 公开基准报告
第 10-12 周 按 C1/C2 结果决定：收窄战场 or 重写命题
```

**决策点**：第 6 周（C1 出结果）和第 10 周（C2 出结果）。

- 若 **A 组（可判断）增益衰减、B 组（外部事实）不衰减** → 命题成立，Runtime 方向确定，可对外主张；
- 若 **B 组增益也消失** → 那些"缺失事实"其实模型能推出来，**立即重写命题**，不要在错误方向上继续做工程。

## 一句话

> **不要问「还能加什么能力」，要问「哪个能力是我有而模型永远学不会的」。**
> 目前只有一个候选：**观察里没有、只有环境才知道的验证事实**（缺失的外部证据 / 权威状态 / 因果关系 / 来源身份）。
> 把它做成别人能用的 Runtime，并且让第三方能验证它——这是唯一值得投入的方向。
