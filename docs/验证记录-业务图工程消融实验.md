## 一、 实验目的与被测对象

本实验旨在**严格量化验证“业务逻辑图工程（点-边-图拓扑驱动）”相较于“传统逐步盲猜探索（Baseline）”在真实交互中的客观代差与优势边界**。

### 1.1 被测场景：受控企业云资源部署向导 (`business_wizard.html`)
该场景模拟了典型的深层复杂 Web 业务流，包含 4 个核心业务状态：
1. **State 1 (`ENTRY_STEP_1`)**：服务基础信息录入（集群标识、邮箱），放置有干扰外链；
2. **State 2 (`STEP_2_ENV`)**：部署规格选择（动态单选联动，未选择直接下一步会触发前端门禁校验拦截）；
3. **State 3 (`STEP_3_CONFIRM`)**：高危生产安全审查阻断（下一步按钮初始处于 `disabled`，必须先触发并确认模态弹窗后方可放行）；
4. **State 4 (`STEP_4_DEPLOY`)**：触发异步部署流水线并产出结果凭据 `DEPLOY_SUCCESS_TOKEN_9988`。

### 1.2 对照组设定
* **A 组（传统逐步盲猜探索 Baseline）**：
  不具备全局业务因果图，进入每个阶段依赖 `world_guide` 与 `world_find` 探索，在第 3 步遭遇阻断后触发自愈重试机制。
* **B 组（业务逻辑图工程驱动 Graph-Driven）**：
  持有预先定义的业务因果拓扑图（含节点签名、前置依赖与动作因果流），沿拓扑路径推进，利用聚合批操作与小票契约闭环。
* **C 组（毒化断边与自愈压力测试 Poison Resilience）**：
  人为在因果图中注入失效的过时边（点击不存在的废弃按钮），检验图驱动引擎的熔断与容错自愈能力。

## 三、 实测结论与深度分析

### 3.1 结论一：业务因果拓扑可消除无谓试错，实现断代级提速（提速 57.6%）
* **耗时对比**：A 组 20.86s vs B 组 8.84s。
* **差异根因**：传统 A 组由于不知道“第 3 步发布前需要先做安全授权审查”，盲点下一步按钮被 `disabled` 状态拦截（触发 `unchanged`），被迫重新扫描寻找前置依赖；B 组沿预定因果边明确知道“进入该步骤必须先走弹窗授权分支”，直接沿主线执行，**将多步业务的试错成本彻底降为 0**。

### 3.2 结论二：交互轮次显著收敛（降低 30%），为弱模型提供了生存空间
* 从 30 轮 MCP 往返减少至 21 轮。
* 轮次的减少意味着更少的 LLM 决策点，显著降低了弱模型（如 Flash / Haiku 量级）在长链路操作中发生注意力漂移或陷入循环的概率。

### 3.3 结论三：当前 Token 压缩仅 8.2% 的根因与后续优化空间
* **现象**：虽然轮数下降了 30%，但总通信字符量仅下降了 8.2%（72.8KB $\to$ 66.8KB）。
* **技术诊断**：
  * 在当前实现中，B 组虽然有了因果边规划，但在找元素时仍然调用了标准的 `world_find`，每次调用仍返回了较重的 `status` 状态卡与候选属性元数据；
  * **启示**：在下一代图工程中，如果已确认的边能够直接复用**稳定指纹缓存（Fingerprint Direct Hits）**绕过全量 `world_find` 元数据交互，Token 传输量将进一步迎来 50%+ 的断崖式压缩。

### 3.4 结论四：防毒化与 Fail-Fast 熔断机制经受住考验（C 组）
* 当人为注入一条指向不存在按钮的毒化边时，底层聚合队列严格遵守“任一步出错即停”的保护规则，于 **2,497ms** 内精准返回 `page_outcome: errored`；
* 图引擎没有陷入重试死循环，而是平稳降级回实时探针，自愈完成任务。
* 证明了架构设计中的铁律：**“死图不会带偏 Agent，实时小票拥有最高一票否决权”**。
