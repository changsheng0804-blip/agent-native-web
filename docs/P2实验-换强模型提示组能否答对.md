# P2 实验:换更强的模型,提示组能否答对?

> 日期:2026-09-08 · 脚本:`mcp/experiments/three_questions.py`(API 版)、
> `mcp/experiments/harness_p2_driver.py` + `harness_p2_launch.py`(子代理 harness 版)
> 原始数据:`three_questions_results-{glm53-n60,kimi27,glm53-final,kimik3b}.jsonl`、
> `p2_harness_results.jsonl`
> 复现:`python mcp/experiments/three_questions.py --model glm-5.3 --runs 10 "--tag=-glm53-n60"`

## 要回答什么

[三问实验](三问实验-缺失事实能否被推理.md) 的结论是「提示救不了事实缺失」,但它只有一个模型
(kimi-k2.7-code)、每组 3 次。**P2 是这个结论的证伪测试**:如果换成更强的模型,提示组(C)也能答对,
那么"事实缺失"就不是护城河,只是弱模型的能力问题——方向该收。

这是三问实验自己写下的下一步:「若换强模型后 C 组仍然答不出,则这一层不会被 scaling 吃掉
——那才是护城河成立的最终证据」。

## 结果:两种方法互相印证

### 方法 A:API 版(脚本直连模型 API)

**主结果:glm-5.3,每组每场景 10 次(共 60 次运行)**

| 场景 | N 无事实 | F 有事实 | C 提示组 |
|---|---|---|---|
| ledger(余额 ¥100 vs 账本 ¥0) | **0/10 (0%)** | **10/10 (100%)** | **0/10 (0%)** |
| async(显示已提交 vs 后台失败) | 6/10 (60%) | **10/10 (100%)** | **0/10 (0%)** |
| **总体** | **6/20 (30%)** | **20/20 (100%)** | **0/20 (0%)** |

统计检验(单侧 Fisher 精确检验):

| 对比 | ledger | async |
|---|---|---|
| F(有事实) vs C(提示) | p=0.0000 | p=0.0000 |
| C(提示) vs N(无事实) | p=1.0000 | p=1.0000 |

**C 组与 N 组无任何差异(p=1.0),与 F 组的差距极显著。**

三模型对照(每组每场景 3 次):

| 模型 | N | F | C |
|---|---|---|---|
| kimi-k2.7-code(原实验) | 2/6 (33%) | 6/6 (100%) | 0/6 (0%) |
| glm-5.3 | 2/6 (33%) | 6/6 (100%) | 0/6 (0%) |
| **kimi-k3** | 2/6 (33%) | 6/6 (100%) | **1/6 (17%)** |

kimi-k3 唯一那次"C 组答对"经逐条审计是**错误推理蒙对**:它说
「未观察到导出任务成功的反馈……因此判定为失败」——用"没看到成功"推出"失败",
这不是拿到事实,是瞎猜碰巧撞上。

### 方法 B:子代理 harness 版(零外部 API 成本)

**做法**:每个格子起一个**隔离的 world**(独立端口 + 独立浏览器上下文),
由**不带上下文的子代理**当 harness——它不知道真相,只能通过 `world_proxy` 的 HTTP 端点调用
`world_*` 工具观测页面,最后给出答案。页面与 API 版同源(同一夹具),但做了两处防泄漏:

1. **夹具脱敏**:剥掉 HTML/JS 注释(原注释写着"真实账本与页面显示可能不一致"= 泄题),
   以中性路径 `/portal` 提供;
2. **真相不可达**:只暴露页面本身与 `/api/export`(202,不泄题),**不暴露 `/api/ledger`**
   ——API 版里模型只有 `world_act`,本就碰不到后端账本,这里保持同等观测面。

**结果(每组每场景 3 次,共 18 次运行)**:

| 场景 | N 无事实 | F 有事实 | C 提示组 |
|---|---|---|---|
| ledger | **0/3** | **3/3** | **0/3**(3 次里 2 次答"不确定",1 次答"¥100") |
| async | 3/3 | **3/3** | **0/3**(3 次全部"不确定") |
| **总体** | **3/6** | **6/6** | **0/6**(6 次里 5 次"不确定") |

**两种方法结论一致**:C 组 = 0%,F 组 = 100%。

C 组的产出性质(harness 版逐条看):

- ledger/C:**没有一次答出 ¥0**。两次明确"不确定",一次把页面的缓存值 ¥100 当成答案(答错)。
- async/C:**三次全部"不确定"**。它们做了 1~8 分钟轮询,确认页面永远停在「排队中」,
  没有任何终态信号,于是拒绝猜测。

**这正面验证了价值主张**:提示让模型**知道自己不知道**(不确定 5/6),但**不知道答案**(正确 0/6)。

## 结论:验证成功了一半(按场景分开看)

**两个场景的证据强度不同,不能笼统说"全部验证成功"。**

### ledger 场景:【已确认】验证成功

问题「这个账户当前可用余额是多少?」的**答案空间很大**(任意金额),
而且**真相(¥0)与页面显示(¥100)相反**,先验也不站在 ¥0 这边——
一个不看页面的模型会答 ¥100,一个看页面的模型也答 ¥100,都错。

| 组 | 结果 | 说明 |
|---|---|---|
| N 无事实 | **0/10 + 0/3** | 全部答 ¥100 或"不确定",没有一次答出 ¥0 |
| C 提示组 | **0/10 + 0/3** | 提示只让它们更谨慎,仍然没有一次答出 ¥0 |
| F 有事实 | **10/10 + 3/3** | 给了权威账本就全对 |

**这是干净的证据:答案(¥0)确实不在页面上,再强的模型 + 再谨慎的提示都产不出它,
只有把事实喂进去才产得出。** 护城河这一层成立。

### async 场景:【不可用】这个场景测不出结论

async 问的是「导出任务成功了吗?」——**答案空间只有两个值,而真相("失败")恰好等于先验**。

一个**什么都不看、纯凭先验**的模型,只要遵守"没证据不能断言成功",就会答"失败"并撞对。
于是这一格**无法区分**"我拿到了事实"和"我只是保守":

1. **N 组的高分不可解释**:API 版 N=6/10,6 次里 4 次只回了一个词(无任何推理过程);
2. **保守推理也会撞上正确答案**:真相是"失败",而"我没观察到成功证据,所以不能算成功"
   **恰好也指向"失败"**。harness 版 N 组 3/3 答"失败",走的正是这条路径
   ——它们自己都标注了「这是合理但非事实的推理」。

**所以 async 这一格既不能证明"模型知道",也不能证明"模型不知道"。**
根因不是"猜中率 50%",而是**真相落在先验那一侧**:不需要任何事实就能命中。

### 合起来怎么说

- **"有些答案不在页面上,模型推不出来"——在 ledger 上被证实。**
- **"提示能替代事实"——被否定**:C 组在两个场景、两种方法、三个模型下正确率全为 0。
- **"不会被 scaling 吃掉"——成立**:换 glm-5.3 / kimi-k3 后 C 组仍然 0/20。
- 但**证据主要由 ledger 一个场景承担**;async 只是"与结论不矛盾",不是"支撑结论"。

诚实说:**这一轮的结论强度取决于你信不信 ledger 这一个场景。**
它干净、可复现、两种方法一致,但毕竟是单一形态。

### 一个更根本的问题:这个设计能不能证伪"模型推不出来"?

值得先承认:**"模型推不出来"在实验里永远无法被正面证明,只能被反复证伪失败。**
我们观察到的是"这次没推出来";推不出来可能是因为"真的推不出来",
也可能是因为"提示词没给对""模型没认真想""采样运气不好"。

这个测试能做的,只是**持续尝试推翻它,而每次推翻都失败**。
所以正确说法是:**"在这三个模型、两种方法、13 次尝试下,没有人推出来"**
——而不是"任何模型都推不出来"。后者是更强的命题,本实验给不出。

据此,更严格的判据应该是:

| 判据 | 说明 |
|---|---|
| 答案空间大 | 排除"猜中就赢"(ledger 满足:任意金额) |
| 真相与先验相反 | 排除"什么都不做也命中"(ledger 满足:先验指向 ¥100) |
| 有过强模型对照 | 排除"只是模型不够强"(已做:3 个模型) |
| 有提示工程对照 | 排除"只是没提示好"(已做:1 句谨慎提示;**未做更强的提示工程**) |
| 多次重复 | 排除采样运气(每组每格 3~10 次) |

**ledger 满足前三条,第四条只做了一个很弱的版本。** 这是本轮最大的方法论缺口:
如果换成"让模型自己反思/多轮追问/CoT 深挖",结果会不会变?本实验没有测。

## 一个必须先说清的问题:N 组的 30% 是能力吗?

async 的真相("失败")**恰好落在先验那一侧**——一个不看页面、只凭"没证据不能说成功"的模型
就会答"失败"并命中。API 版 N 组 6/10 里,**4 次只回了一个词「失败」**(长度 ≤8 字,无任何推理)。
**所以这一格的正确率无法归因给"能力"或"知识"。**

harness 版 async/N 3/3 答"失败",走的正是"没有成功证据 → 不能算成功"这条路径
(它们自己标注了「合理但非事实」)。**这意味着 async 的 N 组和 C 组在这个场景上无法区分**:
两者都答"失败",但一个靠先验,另一个靠被要求谨慎。**这一格的信息量为零。**

真正能区分能力的是 ledger 题(自由作答,无猜中捷径,真相 ¥0 与页面 ¥100 相反):
**N 组 0/10,F 组 10/10,C 组 0/10。**

→ 这条教训已记入设计缺陷(见下表 #9):**真相不能等于"保守默认答案",否则测不出事实的价值。**

## 实验过程中发现并修正的缺陷(自我审计)

这一轮的价值有一半在这里。**修之前,这轮实验给出过错误结论。**

### API 版的 6 个缺陷

| # | 缺陷 | 后果 | 修正 |
|---|---|---|---|
| 1 | GLM 拒绝只有 system 的对话(400/1214) | 18 次运行全失败 | 任务改为 system+user 两条消息 |
| 2 | `max_steps=3` 太小,模型还在重试就被截断 | 空回答被当成"答不出" | 提到 8 步 + 循环后强制收尾(去工具再问一次,含重试) |
| 3 | 判定分支顺序错:全零时先命中"C≈F" | **把失败实验判成"提示可替代事实→方向该收"** | 先检查 F 组是否达标,不达标一律判"实验无效" |
| 4 | ledger 判分:把"刷新余额"按钮(el_11)"的 11 当金额 | 正确答案判成错 | 只在货币/余额语境取金额,并剔除讲旧值的句子 |
| 5 | async 判分:先匹配关键词,命中"从未出现成功的提示" | **结论"失败"被判成"成功"(方向相反)** | 改为判定"模型给出的结论"(结论行/显式标记) |
| 6 | async 判分:"表明任务最终成功或失败"里的"最终成功"被当结论 | 不确定被判成错 | 收紧结论标记;并锁定 30 条真实输出做回归 |

**第 3、5 条是"让实验看起来更支持我"的反方向缺陷**:如果没发现,我会拿一个"方向该收"的假结论去改产品方向。
第 5 条尤其危险——它把与结论相反的词判成答案。

缺陷 4-6 已锁定为回归测试:`mcp/experiments/test_three_questions_judge.py`(30 条真实模型输出,30/30 通过),
并已登记进离线门禁。

### harness 版的 2 个缺陷(更隐蔽)

| # | 缺陷 | 后果 | 修正 |
|---|---|---|---|
| 7 | 子代理能读夹具源码(注释写着"真实账本可能与显示不一致") | 第一次试跑直接看源码猜出题意图 | 夹具脱敏(剥注释)+ 中性路径 |
| 8 | **子代理能读仓库源码**(`three_questions.py` 里写着 `truth: "失败"`) | **async/N 前 3 次是看着答案答的,必须作废** | 任务里加"禁止读文件系统"硬约束;重跑 3 次 |

### 场景设计缺陷(这轮才看清)

| # | 缺陷 | 后果 | 修正 |
|---|---|---|---|
| 9 | **async 的真相等于"保守默认答案"** | 真相="失败",而"我没看到成功证据"也会指向"失败" → 该场景无法区分"拿到事实"与"保守推断" | 该场景本轮**不可用于判定**;换场景需让真相与保守默认相反(如"实际成功但页面无成功信号") |
| 10 | **二选一本身不构成缺陷,问题在于"答案空间"** | 见下 | 判据应建立在**答案空间够大**的题上 |

第 9 条的机制值得说清,因为它不是"猜中率 50%"那么简单:

async 的**先验**就已经是"失败"了——不需要看任何页面。一个什么都不做的模型,
只要遵守"没证据不能断言成功",就会答"失败"并撞对。所以这一格**无法区分**
"我拿到了事实"和"我只是保守"。这是**先验与真相重合**,不是"运气"。

**关于二选一(订正)**:二选一本身不是缺陷。一个从不观察页面、只凭先验的基线,
在二选一上也能稳定命中——问题不在于"猜中率 50%",而在于**答案空间只有两个值,
真相又恰好是先验那一侧**。判据应建立在答案空间够大的题上(如报一个金额):
先验蒙不中,只有真拿到事实才答得出。

第 10 条是对本报告早先措辞的订正:我曾把"二选一"本身当作噪声来源,
更准确的说法是**"答案空间 × 先验位置"决定了这一格有没有信息量**。

第 8 条是这轮最值得记的教训:**"隔离"不能只隔离页面,还要隔离文件系统。**
子代理继承了工作目录,`grep truth` 一下就能拿到答案。作废的那 3 条已在数据里标记
`contaminated: true`,不计入汇总。

## 诚实的边界

| 限制 | 说明 |
|---|---|
| **结论主要靠一个场景** | ledger 是干净判据;async 因真相落在先验侧(不需事实即可命中),本轮不可用(#9) |
| **提示工程只试了一句** | C 组只加「谨慎判断,不确定就说不确定」;**多轮追问 / 自我反思 / CoT 深挖未测**——这是本轮最大缺口 |
| **"推不出来"只能被反复证伪** | 观察到的是"这 13 次没人推出来",不是"任何模型都推不出来" |
| 单任务形态 | 两个场景都是"页面显示 vs 后端真相"的对抗;别的形态(多步任务、跨会话)未测 |
| 两种方法成本不同 | API 版消耗外部额度(约 75 万输入 tokens);harness 版零 API 成本,但执行者是有推理能力的子代理 |
| 样本仍小 | ledger 上 C 组 0/13、F 组 13/13、N 组 0/13;信号一致但样本小 |

## 对方向的含义

1. **P2 已回答(ledger 场景)**:这一层不会被 scaling 吃掉。
2. **价值主张维持不变**:卖的是"提供模型无法推理出来的事实",不是"防止模型乱猜"。
3. **下一步三件事**:
   - **补更强的提示工程对照**(多轮追问 / 自我反思 / CoT 深挖)——**这是最关键的一件**,
     因为它是"推不出来"的最后一个可信替代解释;
   - **补一个干净场景**替代 async(真相与先验相反),让结论不再只靠 ledger 一条腿;
   - **换任务形态**(多步、跨会话、工具返回被污染)与**事实的获取成本**。
4. **方法学沉淀**:
   - 子代理隔离必须同时管住**页面**和**文件系统**,任一泄漏结果作废;
   - 场景设计必须检查两件事:**答案空间够大**、**真相不在先验那一侧**;
   - 表述纪律:说"这 N 次没人推出来",不说"模型推不出来"。
