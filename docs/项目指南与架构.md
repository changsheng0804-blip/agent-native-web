# Agent-Native Web 项目指南与架构

## 1. 项目是什么

Agent-Native Web（智能体原生网页）把普通网页转换成智能体可以直接活动的“原生网页世界”。它的重点不是替代浏览器自动化，而是为智能体提供更快的页面导览、更明确的目标定位和更及时的操作反馈。它不要求网站预先适配，适合网页没有提供专用智能体接口的场景。

核心闭环是：

```text
快速导览 → 按需定位 → 执行动作 → 实时反馈 → 持续决策
```

**对外默认协议只有 6 个词(阶段 B 收口):**

```text
open → guide → find → act → outcome → close
```

- `world_find`:定位构件(matches[] + ambiguous)
- `world_act`:唯一行动入口(kind=click|fill|press|batch_fill;`steps=[...]` 聚合多动作,一个往返)
- `world_outcome`:幂等读最近一张统一后果卡
- 每次动作都返回同一张卡,`page_outcome` 五态(progressed/challenged/errored/uncertain/unchanged)
- 旧 22 个 `world_*` 工具全部保留为 `[内部/调试]`;`AGENT_WORLD_LITE=1` 时只暴露 6 词

项目最初的重要动机是降低视觉识别和重复上下文带来的 Token 消耗；当前更重要的价值是减少复杂网页中的定位困难、延时轮询和“无反馈即猜测成功”造成的错误。

## 2. 目录结构

```text
extension/                  浏览器注入内核与扩展
  engine/                   扫描、语义、可见性、空间和查询
  content/                  动态变化观察与运行时调度
  api/                      window.agentWorld 接口
  all-in-one.js             自动合并后的注入文件
  scripts/                  构建脚本
mcp/                        MCP 服务器与测试脚本
  server.py                 22 个 world_* 工具的服务器入口
tests/fixtures/             本地动态网页测试夹具
skills/agent-world/         给智能体使用的标准技能包
docs/                       设计、实战、安全和验证文档
```

旧版 `agent-runtime-extension` 已从活动目录移除；历史版本仍可通过 Git 提交记录查看。

## 3. 最快开始

### 安装依赖

```bash
pip install mcp playwright pillow
playwright install chromium
```

> `pillow` 用于视觉 diff 证据与 Set-of-Mark 标注绘图(PR #2 引入的必须依赖,缺失会导致 server.py 启动即崩溃)。

### 注册 MCP 服务器

把下面命令加入 MCP 客户端配置：

```json
{
  "mcpServers": {
    "agent-world": {
      "command": "python",
      "args": ["F:/成果库/Agent 友好插件/mcp/server.py"]
    }
  }
}
```

重启 MCP 客户端后即可看到 `world_*` 工具。

### 第一次使用

1. 用 `world_open` 打开网页，默认 `ready_policy=action`：达到可操作状态就返回；只有确实需要完整稳定页面时才指定 `ready_policy=stable`。
2. 先用 `world_guide` 或 `world_find` 定位目标；`world_map` 只在需要完整地图时调用。页面扫描会在后台渐进补齐。
3. 用 `world_entity` 查看目标构件详情。
4. 用 `world_click`、`world_fill` 或 `world_press` 执行动作。
5. 用 `world_state` 读取最新页面状态，用 `world_change_digest` 读取变化摘要。
6. 用 `world_evidence` 读取动作前后证据，确认动作是否真正生效。
7. 用 `world_guide` 根据任务生成当前页面的短导览和下一步建议；重复任务可能出现已实时验证的 `route_hint`（历史路线提示），但不会替代当前页面事实。
8. 用 `world_close` 关闭不再使用的网页世界。

## 4. 工具分组

| 分组 | 工具 | 用途 |
| --- | --- | --- |
| 打开与管理 | `world_open`、`world_list`、`world_close` | 创建、查看和关闭网页世界 |
| 查询 | `world_entities`、`world_entity`、`world_layers`、`world_map`、`world_resolve` | 找构件、看详情、看区域和语义结构 |
| 页面信道 | `world_state`、`world_change_digest`、`world_evidence` | 分别读取页面状态、变化摘要和操作证据 |
| 任务导览 | `world_guide` | 根据当前任务组合三条页面信道，返回相关区域、候选入口和下一步 |
| 变化与验证 | `world_changes`、`world_wait`、`world_screenshot` | 读取原始增量变化、等待条件和视觉兜底 |
| 操作 | `world_click`、`world_fill`、`world_batch_fill`、`world_press` | 点击、填表、批量填表和按键 |
| 导航与调试 | `world_navigate`、`world_click_at`、`world_eval` | 页面导航、坐标兜底和受控调试 |

“构件”是网页中可识别的元素，例如按钮、输入框、弹窗或链接。“稳定指纹”是根据语义属性和祖先路径生成的第二种定位方式，用于同一网站再次进入时认路。

## 5. 当前能力

- 编号驱动的网页查询和操作。
- 动态页面增量更新与变更游标。
- 独立的页面状态、变化摘要和操作证据信道。
- 点击、填表、按键后的生效报告。
- 事件驱动等待，避免无意义的反复查询。
- 页面地图、区域钻取和构件详图。
- 持久化登录态、可见浏览器和独立 profile。
- iframe 感知、反爬异常提示和截图兜底。
- IPI 伪隐藏内容过滤，但不宣称能防御所有提示词注入。

其中最核心的三项能力是：

- **页面导览图**：先给智能体页面整体结构和区域入口，不要求它读取所有元素。
- **实时变化反馈**：用增量事件和事件驱动等待，尽快告诉智能体页面发生了什么。
- **操作生效报告**：点击、填表和按键后返回变化证据，减少智能体凭空判断成功或失败的空间。

### 流畅执行优先

`world_open` 的 `ready_policy` 分三级：`action`（默认，先可操作）、`terrain`（任务区域可查询）、`stable`（兼容旧流程，等待页面稳定）。运行时先扫描视口和高优先级交互元素，再在后台分段扫描完整页面；扫描更新 `scan_revision`，不会阻塞动作。

动作工具可选 `wait_policy=receipt`：先返回 `action_id`，随后用 `world_outcome(action_id=...)` 查询最终后果卡。默认 `confirmed` 行为保持不变。同一网页世界的写操作仍按提交顺序执行。

当前版本的浏览器内监听和后台扫描是并行的；Playwright（浏览器控制库）的服务器调度仍使用单一专用线程，因此不同网页世界暂时不会真正并行执行。这样先保证线程安全，按网页世界拆分执行器属于后续阶段。

导航记忆只保存在本机 `mcp/memory/navigation_graph.json`（不入库、不跨用户共享），至少两次成功且当前指纹验证通过才会在 `world_guide.route_hint` 中提示；验证失败会标记过期，不会静默沿用。

## 6. 开发规则

修改 `extension/engine`、`extension/content` 或 `extension/api` 后，必须重新生成合并文件：

```bash
python extension/scripts/build_all_in_one.py
node --check extension/all-in-one.js
```

MCP 服务器从 `extension/all-in-one.js` 读取注入内核。分文件源码与合并文件必须保持同步。

## 8. 安全与限制

- CDP 只能连接独立 profile，不能连接日常浏览器。
- CDP 调试端口必须绑定本机地址，并在使用后关闭。
- CDP 场景禁用 `world_eval`，避免任意 JavaScript 读取登录会话内容。
- `world_eval` 在普通场景仍是调试后门，不应把它当作安全边界。
- 每个网页世界约占用 200 MB 内存，能并行打开的数量取决于机器内存。
- 反爬页面可能只返回简化内容；这是网页环境限制，不代表扫描结果等于真实页面。
