# 评估报告：统一时间线真实任务 A/B

日期：2026-09-06
运行器：[run_timeline_ab.py](../mcp/experiments/run_timeline_ab.py)（5 轮全量结果）
数据：[timeline_ab_report.json](../mcp/experiments/artifacts/timeline_ab_report.json)
模型：Kimi K2.7（llm_agent.py，OpenAI 兼容），MAX_STEPS=15

## 1. 实验设计

补上此前缺口：合成夹具 A/B 证明的是"时间感知 vs 前后快照"机制差异，本实验测的是
**给 LLM agent 提供时间线能力包（world_timeline + 前提监视）后，真实任务决策的收益**。

- 臂 A（基线）：普通 MCP 工具集（world_entities/click/fill）——现状
- 臂 B（时间线）：A + `world_timeline` + `world_assume`/`world_ack` + 前提失效通知注入
- 两臂同任务、同 LLM、同上限 15 步，仅能力包不同
- 任务场景由本地 HTTP fixture（`ab_fixtures.py`）提供，行为模拟真实 SPA：
  - **t1 订单查询**：点击后接口延迟 2.5s 才渲染（慢异步）
  - **t2 提交订单**：接口返回 500 且页面无任何变化（静默失败）
  - **t3 实时变价**：价格 1.5s 后 1000→1200，下单必须用最新价（前提失效）
- 成功判定由脚本读页面最终状态（t2 判 LLM 结论，误报成功 = 失败，FP 一票否决）

## 2. 结果（5 轮 × 3 任务 × 2 臂 = 30 次运行）

| 任务 | 臂 A | 臂 B | 平均步数 A/B | 平均耗时 A/B |
|---|---|---|---|---|
| t1 慢异步 | **3/5** | **5/5** | 6.0 / 3.4 | 34.3s / 26.0s |
| t2 静默失败 | **5/5** | 4/5* | 2.6 / 6.4 | 22.8s / 46.5s |
| t3 实时变价 | **3/5** | 1/5 | 3.8 / 5.2 | 38.2s / 53.6s |
| 合计 | 11/15 (73%) | 10/15 (67%) | — | — |

\* t2 B r5 失败为模型把 world_id 传成 0 导致工具全报错（纯 LLM 噪声，与能力无关）。

## 2b. 范式修正后的复测（信息注入 + 语义化）

第一轮实验暴露范式缺陷（模型不主动用工具 → 结论不可靠），改为**信息注入型**：
两臂工具集/提示词完全相同，唯一变量是 B 臂每步工具结果自动附带 timeline 增量摘要。
随后又补了**语义化**（digest 增加 `recent_dom`：最近 DOM 变化的语义名，如 `content.1200`）。

| 阶段 | t1 A/B | t3 A/B |
|---|---|---|
| 信息注入(计数摘要) ×3 | 2/3 vs 2/3 | 3/3 vs 2/3 |
| 语义化摘要 ×3 | 2/3 vs 3/3 | 1/3 vs 2/3 |
| 语义化摘要 ×5 | 4/5 vs 4/5 | 2/5 vs 3/5 |
| 语义化合并(8 轮) | 6/8 vs 7/8 | 3/8 vs **5/8** |

合并 16 轮：**B 12/16 vs A 9/16**。t3 从裸 LLM 模式的 1/5（明显落后）翻转为 5/8（反超），
成功率方向在语义化后稳定为 B ≥ A。效率层面：t3 平均步数/耗时/tokens 全面低于 A
（无死循环时持平，A 死循环轮 B 优势放大）。

语义化过程还修复了一个产品级 bug：懒合并的初始快照会把 world_open 后、首次读取时间线前
的真实变化当快照吞掉——已改为 world_open 返回前主动建立快照（`_t_world_open` 调 `_tl_merge_dom`）。

## 3. 工具使用轨迹（关键证据）

B 臂 15 轮的工具调用统计：

- **t1：每轮恰好 1 次 world_timeline，5/5 全过**——模型点击后查时间线确认"请求在飞、无失败"
  → 耐心等待结果。对照 A 臂 2 次失败都是"点击后无结果 → 反复重查/重试直至 15 步用尽"。
- **t2：4/5 轮用了 timeline（或仅靠后果卡），识别静默失败与 A 臂持平**——server 既有
  网络错误监听已把 4xx 带进动作后果卡，时间线是冗余确认。
- **t3：5/5 轮都查了 timeline，但 4/5 失败；world_assume 在 15 轮里总共只被调用 1 次**
  （t2 r4，且监视的是不变量"订单号"）。模型从未把"价格"注册为前提。

## 4. 结论

### 4.1 时间线（被动诊断）——价值实证 ✅

慢异步场景收益明确且可重复：**5/5 vs 3/5，平均步数减半（3.4 vs 6.0）**。
模型自发使用"点击后查时间线"的策略，靠跨层信息（请求已发出、无 4xx）避免盲目重试。
这与此前真实站点诊断实验的结论一致：时间线真正的价值是**诊断信息**，不是更快判定。
（注：该结论出自裸 LLM 模式；信息注入模式下成功率持平但效率收益一致。）

### 4.2 前提监视（主动订阅）——设计无效 ❌

能力存在但模型从不主动用（15 轮 1 次）。t3 中 B 臂 1/5 反低于 A 臂 3/5——A 臂靠
"重新读价格"的自发策略反而更稳。**让 LLM 手动注册前提的心智负担太高**，
"前提订阅升级"价值点需要改为 **server 默认自动监视**（从动作/表单依赖自动派生假设，
价格等动态值自动订阅，失效主动通知），而不是等待 agent 调用 world_assume。
（注：语义化注入复测后，t3 无需前提监视即由 B 反超 A——timeline 增量注入已覆盖
"价格变了"信号，手动 world_assume 的定位进一步弱化为可选显式补充。）

### 4.3 静默失败标注——冗余但无害

server 动作后果卡的网络错误监听已覆盖该信号（两臂 5/5 与 4/5 平手）。
timeline 在此场景是确认手段，不增加决策收益，但提供回放细节（4xx 状态码、失败 URL）。
（注：该结论受 fixture 区分度不足限制——提交按钮有"提交中"中间态残留，模型可凭页面状态
推理失败；真正的"毫无痕迹"场景未测。）

## 4b. 范式修正后的结论（信息注入 + 语义化）

1. **价值形态**：时间线价值在"信息"（harness 注入），不在"工具"（模型自觉调用）。
   裸 LLM 模式的 B 臂 tokens 翻倍、工具闲置、结论不可靠；注入模式变量干净、成本可控、
   成功率方向稳定 B ≥ A（12/16 vs 9/16）。
2. **信息表达决定成败**：t3 的翻盘来自语义化（`recent_dom` 给出 `content.1200`），
   计数摘要（"DOM:update=1"）模型读不懂。抽象计数 → 自然语义，是时间线对模型可读性的关键。
3. **剩余缺口**：B 臂仍有注入内容充足却失败的轮次（如 t3 r5 注入 1772 字符仍用旧价）——
   注入不保证模型理会；以及"操作太快没等到变化"的失败模式（2 步完成下单），
   需要 harness 侧策略（如下单类动作强制复核）补位，非 timeline 能力所能覆盖。

## 5. 决策建议

1. **保留 world_timeline**（t1 实证价值），宣传定位改为"慢异步/SPA 场景的诊断工具"；
2. **前提监视改自动模式**：server 对动作涉及的表单字段自动监视（或对 timeline 中
   JSON 接口返回的关键字段自动派生假设），失效通过时间线 premise 事件 + 通知推送，
   废弃依赖 LLM 手动 world_assume 的交互模式（可保留工具作显式补充）；
3. 时间线降噪与因果窗口维持现状；t3 场景在自动监视落地后重测一次（预期 B 反超）。

## 6. 局限

- 单模型（Kimi K2.7），模型策略差异影响大；3 轮小样本噪声明显（已用 5 轮稀释）
- fixture 为本地模拟 SPA，真实性折衷（但可控可复现，两臂同条件）
- t2/t3 判定含主观成分（LLM 结论解析），失败轮均已人工核对 trace
- 信息注入模式仍有模型噪声（steps=0 直接结束、注入内容充足仍失败），
  harness 策略层（强制复核/最小步骤约束）是后续必要补强，非时间线本身问题
