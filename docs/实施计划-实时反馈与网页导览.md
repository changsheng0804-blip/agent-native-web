# Agent-Native Web MCP 实施计划

## 目标

让智能体在网站没有主动适配 WebMCP 的情况下，也能快速进入复杂网页、找到任务目标、执行操作，并获得足够准确、及时、无歧义的反馈。

## 非目标

- 不把项目发展成完整浏览器自动化平台。
- 不把安全研究扩展成独立的浏览器安全产品。
- 不追求导出页面的全部元素。
- 不承诺所有网站都能获得相同质量的结构化结果。
- 不在没有基准测试时宣称固定 Token 节省比例。

## 总体路线

```text
基线测量
  → 反馈证据层
  → 页面导览层
  → 事实/推断/证据分层
  → WebMCP 双通道调度
  → 多网站基准与持续回归
```

## 阶段 0：建立基线和统一数据模型

### 目标

先把“快、准、无歧义”变成可测量指标，避免凭单个网站体验判断项目效果。

### 任务

- 建立固定真实网站集合：简单页面、重型 SPA、控制台、表单页、多 iframe 页面。
- 为每个网站建立无破坏性任务，例如找到入口、打开菜单、填入非敏感关键词、读取页面状态。
- 同一任务分别记录原生浏览器和 Agent-Native MCP 的过程。
- 统一记录页面加载时间、首次正确定位时间、首次反馈时间、读取内容量、失败类型和恢复步骤。
- 为所有返回信息定义来源类型：`fact` 页面事实、`inference` 页面推断、`evidence` 操作证据、`untrusted` 不可信文本、`action` 可执行动作。

### 核心指标

| 指标 | 含义 |
| --- | --- |
| 首次正确定位时间 | 从打开页面到找到正确目标的时间 |
| 首次反馈延迟 | 动作发出到得到有效页面反馈的时间 |
| 定位歧义率 | 目标匹配到多个候选且需要人工判断的比例 |
| 假成功率 | 实际未生效却返回成功的比例 |
| 假失败率 | 实际生效却返回失败的比例 |
| 无关读取比例 | 为完成任务读取但不相关的页面信息比例 |
| 恢复时间 | 一次操作失败后恢复到可继续状态的时间 |

### 通过标准

- 所有测试场景都能区分“成功、变化但不确定、无变化、超时、被阻止”。
- 假成功率为 0，或每次异常都明确标记为不确定。
- Token 只作为附加指标，不作为唯一通过条件。

## 阶段 1：实时操作反馈和证据层

### 目标

把“操作后等待和猜测”变成“操作后接收可追溯证据”。

### 任务

- 统一 `world_click`、`world_fill`、`world_press` 的反馈格式。
- 保留事件驱动等待，继续减少固定延时轮询。
- 将动作前快照、动作后变化和页面 URL 状态关联起来。
- 明确区分 `effected`、`changed`、`no-change`、`timeout` 和 `blocked`。
- 为每条证据增加来源、时间和相关目标编号。
- 对弹窗出现、弹窗消失、输入值进入、URL 变化、ARIA 状态翻转等建立独立证据类型。
- 将“服务器判断”与“页面事实”分开，最终判断权仍交给智能体。

### 计划中的反馈结构

```json
{
  "verdict": "effected",
  "confidence": "high",
  "target": "el_89",
  "evidence": [
    {
      "type": "dialog_appeared",
      "id": "el_120",
      "source": "page_change",
      "elapsed_ms": 210
    }
  ],
  "page_state": "stable"
}
```

### 阶段验收

- 正例不能返回 `no-change`。
- 负例不能返回 `effected`。
- 持续变化页面不能让观察器饿死。
- 反馈中能找到实际变化的构件编号。
- 真实网站和本地夹具都通过同一套判定规则。

## 阶段 2：页面导览和按需理解

### 目标

让智能体先知道页面“哪里有什么”，再读取真正相关的局部内容。

### 任务

- 继续完善 `world_map` 的页面级区域识别。
- 保留“地图提供方向、查询负责细节”的原则。
- 支持页面地图 → 区域范围 → 区域内构件 → 构件详图的钻取链路。
- 为区域补充语义名称、入口数量、可交互元素数量和是否可继续钻取。
- 根据任务关键词提供相关区域候选，但不自动穷举所有子区域。
- 处理纯 `div` 页面、重叠容器、iframe 和超大 `main` 区域。
- 评估导览结果对首次正确定位时间和无关读取比例的影响。

### 阶段验收

- 复杂页面能返回有限数量的主要区域。
- 区域入口可以继续查询到强 ID。
- 地图不会因为追求细分而制造大量伪区域。
- 智能体可以只查询任务相关区域，不必读取全页元素。

## 阶段 3：准确性与防幻觉层

### 目标

让智能体知道“哪些是页面明确告诉我的，哪些只是系统推断的，哪些才是动作证据”。

### 任务

- 为结构化返回增加来源标记和新鲜度信息。
- 页面事实只来自页面结构、属性和可观察状态。
- 页面推断必须带置信度，不能伪装成页面原话。
- 操作证据必须引用动作后的实际变化。
- 页面文本默认属于不可信内容，不能自动成为系统指令。
- 可执行动作只来自已识别且当前可操作的构件。
- 将 `world_eval` 明确隔离为调试能力，不作为普通流程入口。
- 建立假成功、假失败、定位歧义、状态过期和页面重渲染测试夹具。

### 阶段验收

- 不完整页面信息不会被系统包装成确定事实。
- 操作没有证据时不会返回成功。
- 页面中的诱导文本不会改变工具权限或操作范围。
- 反馈能指出“事实、推断、证据和不确定性”的区别。

## 阶段 4：WebMCP 双通道

### 目标

让 Agent-Native Web MCP 成为 WebMCP 的补充和验证层，而不是与其重复建设。

### 任务

- 探测页面是否提供 WebMCP 工具。
- 有明确、可用的 WebMCP 工具时优先走网站原生路径。
- 没有 WebMCP 或调用失败时，回退到结构化查询和模拟操作。
- WebMCP 执行后仍读取页面状态和变化证据。
- 在返回结果中标注执行路径：`webmcp`、`agent-native` 或 `fallback`。

## 阶段 5：持续回归和公开验证

- 固定真实网站基准，不依赖单次演示。
- 每次内核修改自动运行本地夹具测试。
- 定期运行真实网站测试，记录反爬、登录、动态加载和 iframe 差异。
- 公开记录成功、跳过和失败，不只展示成功案例。
- 将测试报告与版本号、浏览器版本和日期关联。

## 安全边界

安全是必要护栏，不是项目主航道：

- 继续限制 CDP 使用独立 profile。
- 继续警告 `world_eval` 的高权限性质。
- 继续把页面自由文本视为不可信内容。
- 顺手修复可低成本解决的注入和越权问题。
- 不把项目宣传为解决所有本地浏览器注入安全问题。

## 当前第一批实施任务

1. 统一反馈枚举和返回字段，补充 `timeout`、`blocked` 与证据来源。
2. 为真实网站测试脚本加入统一计时和指标输出。
3. 为 `world_map` 增加任务相关区域查询的实验接口，不自动细分大区域。
4. 为 `world_entities`、`world_entity` 和 `effect` 增加事实/推断/证据字段。
5. 增加定位歧义、无证据成功和状态过期的本地测试夹具。
6. 完成 WebMCP 能力探测的设计调研，再决定接口实现方式。
