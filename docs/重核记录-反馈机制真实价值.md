# 重核记录：反馈机制真实价值（真实 harness 体验）

日期：2026-09-06 起
方法：本会话的 agent（资源受限模型）作为**真实 harness**，通过 MCP 直连 server，
在真实站点（GitHub git/git）逐机制执行"后果卡/信道输出 vs 页面事实"的交叉核对。
与合成 A/B 互补：合成实验是确认型验证，真实 harness 体验是发现型验证
（能以极低成本暴露合成场景永远发现不了的真实缺陷）。

## 已重核机制

### 1. 后果卡五态判定（page_outcome）——合格 ✅

5 类真实动作（导航/竞态导航/点击/填表/404 导航），五态判定全部正确、无误判：

| 动作 | 判定 | 核对 |
|---|---|---|
| 点击 Pull requests（导航） | progressed/navigation/high | URL 事实准确 |
| 竞态导航（连点 tab） | progressed/navigation/high | after 快照降级后判定仍可靠 |
| 点击未激活 tab | progressed/navigation/high | 判定准确（脚本预期错误，系统无误） |
| fill 搜索框 | progressed/form/high | 781ms，值验证判定 |
| 导航到 404 页 | progressed/navigation/high | URL 变了判定正确；时间线补充 404 真相 |

关键发现：
- **后果卡与时间线的分工**：后果卡回答"动作生效了吗"（生效性），时间线回答
  "世界发生了什么"（事实性）。GitHub 404 页自身渲染 200，只有网络层能区分——
  单靠后果卡会把"导航到 404 页"当普通成功；组合信息后 harness 知道"到了但页面不存在"。
- 导航竞态降级路径（after 轻量快照）实测可靠。
- 遗留：导航动作反馈延迟波动（8-55s，locator 稳定等待 + 网络），有界但需 locator 策略优化。

### 2. world_guide 导览——发现并修复缺陷 ✅（修复后合格）

3 个定位任务（Pull requests / Star / Releases）对比盲查与导览：

| 任务 | 修复前 | 修复后 |
|---|---|---|
| T1 Pull requests | 候选 1 正确（score 16 + href 确认） | 不变 |
| T2 Star | **候选 1 = Notifications（无关），next_action 误导** | **候选 1 = Star 入口（score 6），next_action 正确** |
| T3 Releases | 候选 1 正确（score 11） | 不变 |

根因（埋点实证）：
- `_guide_terms` 对**英文词做停用词子串 replace**——停用词 `"a"` 把 `"Star"` 拆成
  `"st"`，而 "st" 出现在几乎所有元素 name 里（must/requests/star），导致全场 4 分
  大平局，Notifications 凭原始顺序抢到 first。
- 修复三件套：
  1. 英文词改**精确词**过滤停用词（中文段保留子串剔除——中文无空格分隔）；
  2. 候选排序加"命中任务词数"tie-breaker（防御同分）；
  3. `next_action` 保底：只指向"interactive 且命中任务词"的候选，否则提示自行确认。
- 验证：T2 修复后 Notifications 消失、Star 入口第一、next_action 正确；24/24 门禁全绿。

### 3. L3 动作证据卡（world_evidence）——发现并修复缺陷 ✅（修复后合格）

4 个连续动作（2 导航 + 1 无副作用点击 + 1 导航）：

| 动作 | 证据记录完整性 | action_evidence.decision | 与后果卡一致性 |
|---|---|---|---|
| E1 导航 | ✅ before/after/transition 完整 | 2xx→已生效 | 一致 |
| E2 竞态导航 | ✅ 完整（竞态无缺失） | 2xx+接口→已生效 | 一致 |
| E3 点已激活 tab | ✅ verdict=no-change 正确 | **修复前："已生效,继续下一步"；修复后："页面判定动作未生效/存疑…"** | **修复前矛盾；修复后一致** |
| E4 导航 | ✅ 完整 | 2xx→已生效 | 一致 |

缺陷：`_evidence_decision` 只看请求状态码——GitHub 后台轮询全 2xx 时，无副作用
点击被误判"已生效,继续下一步"，与后果卡 `unchanged` 直接矛盾（只读 action_evidence
的客户端会被误导前进）。
修复：decision 融合后果卡判定（page_outcome/effect.verdict），未生效时明确提示
"请求状态不能确认生效（后台轮询/预取也可能 2xx）"。
附带发现：`transition.changes_seq_advanced` 受渐进扫描噪声污染（无副作用点击也为
true）——未影响主判定（verdict 来自后果卡 effect），对 harness 有轻微误导性，低危。

### 4. world_change_digest——发现并修复缺陷 ✅（修复后合格）

同一次真实导航后对比两种摘要表达（change_digest vs timeline digest，同一事件源）：

| 表达 | 修复前 | 修复后 |
|---|---|---|
| change_digest counts | remove 563 / update 1437（无因果语义） | 不变 |
| change_digest key | **空（整页替换全被单条降权误伤）** | **bulk: page-replacement (563+1437)** |
| timeline digest | 状态码/接口/bulk/静默失败齐全 | 不变 |

缺陷：`_event_importance` 对整页替换的 remove 全标 medium（外壳降权防御误伤），
`_change_digest` 的 key 因此为空——导航信号被单条语义过滤漏掉。
修复：key 增加**批量信号归纳层**（同批 remove≥100 且 update≥remove → 直接进 key，
不经过单条语义降权）。
结论：change_digest 与 timeline digest 功能重叠且表达更弱（无状态码/接口/因果窗口），
但修复后至少能给出"整页替换"级判断；harness 注入场景建议以 timeline digest 为主。

## 方法论结论

- 真实 harness 体验的产出效率远高于合成 A/B：四轮重核（后果卡/world_guide/L3证据卡/
  change_digest）共约 15 个真实动作，发现并修复 3 个真实缺陷（guide 分词拆碎英文词、
  evidence decision 与后果卡矛盾、digest key 漏批量信号），零 LLM 成本。
- 局限：单站点（GitHub 语义命名良好，盲查也容易）、单模型视角、无统计显著性——
  发现的问题可靠，但"没发现问题"不等于"没有问题"。
