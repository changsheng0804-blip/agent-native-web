# 渠道对照演示:假成功(同页同点击,四种读法)

> 同一个页面、同一次点击:A 朴素 DOM / P 官方 Playwright MCP / B 后果卡 / C 隐藏真值。
> P 臂为**真实调用** @playwright/mcp v0.0.82 默认配置,原始返回全量引用,可复核。
> 复现命令:`python mcp/demo_showdown.py --case all --report`

## 结论一览

| 场景 | 后端实际 | P 臂返回里有失败原因吗 | B 臂判定 |
|---|---|---|---|
| 显示成功但后端 422 | HTTP 422 | 否(仅 console 计数) | `errored` |
| 按钮变灰但请求 rollback | HTTP 500 | 否(仅 console 计数) | `errored` |
| 202 后异步失败 | HTTP 202; HTTP 500 | 否(仅 console 计数) | `unchanged` |
## 诚实性说明(必读)

1. **P 臂并非毫无信号**:点击返回带有 console 错误**计数**(本页含一条 favicon 404 常驻噪声)。强模型可以据此发起追查;但失败的具体状态码与原因(422/账号已存在)不在返回文本里,需要模型**额外主动调用** 1-3 次工具(读日志文件 → `browser_network_requests` → `browser_network_request` 取响应体)才能拼出。
2. **B 臂把判定与结构化原因放进动作返回本身**。对比点是**信道形态(推 vs 拉)**,不是模型能力——这与本项目 A/B 实验结论一致:依赖模型主动调用验证工具的模式不成立(15 轮仅 1 次)。
3. 快照以**文件链接**返回是 v0.0.82 默认配置在本机的实测行为,可能随客户端/配置而变;本报告全部引用原始返回,不依赖该行为成立与否。
4. 场景 3(202 后异步失败)B 臂同样只给 `unchanged/uncertain`:异步结果追踪是已登记的待补项,两臂在此场景都同样失明,谁也不比谁强。
