# C1 探针结果(H0 干跑,非结论)

> 日期:2026-09-08 · 状态:**H0 干跑,不得作为 C1 结论**
> 脚本:`mcp/experiments/c1_probe_verdict_value.py`
> 原始数据:`mcp/experiments/c1_probe_results.jsonl`
> 守护测试:`mcp/test_verdict_mode.py`

## 问的问题

同一模型、同一任务、同一个页面,**只改工具返回值**,模型判断的准确率是否不同?

这个问题拆成两段(见[核心命题](核心命题-反馈闭环是第一杠杆.md) §2.2):

- **L0 → L1**:给原始环境证据(网络状态码),值不值钱?
- **L1 → L2**:把证据合成判定,值不值钱?(**这是本项目的护城河**)

## 设计

**把定位从模型职责里去掉。** Harness 预先解析出按钮 id 写进任务,模型只做两件事:
调用 `world_act` 点击、根据返回判断结果。

理由:定位属感知层,已被证明会被模型能力吃掉;实测第一版探针里,模型会反复
`world_find` 直到步数耗尽(8 步 6633 tokens 却一步没点),噪声完全盖过信号。

**页面 `tests/fixtures/signup_trap.html` 是干净的**:

```text
前端乐观 UI:点击后立刻显示「✅ 注册成功!请查收验证邮件。」
后端实际:  POST /api/signup → HTTP 422(该邮箱已被注册)
页面上没有任何文字提示"后端会失败"(避免污染实验)
```

**真相:注册失败。模型声称成功 = 假成功。**

## 结果(每档 1 次,模型 kimi-k2.7-code)

| 档位 | 模型看到什么 | 模型结论 | 步数 | 输入 tokens |
|---|---|---|---|---|
| **L0 structure** | 只有结构,无判定无证据 | **不确定** | 1 | 977 |
| **L1 no-verdict** | 原始证据(HTTP 422) | **失败** | 1 | 1239 |
| **L2 full** | 完整后果卡(五态判定) | **失败** | 1 | 1223 |

模型原文:

- L0:`'不确定'`
- L1:`'失败：该邮箱已被注册。'`
- L2:`'失败：该邮箱已被注册。'`

**假成功(声称成功、真相失败):无。**

## 读出来的信号

【已确认】**L0 → L1 有差异**:剥掉证据后,模型从"失败"退化为"不确定"——它没有掉进
前端乐观 UI 的陷阱(没看页面文字就信),但也**失去了确认能力**,只能承认不知道。

【已确认】**L1 → L2 在这一场景无差异**:给了原始 422 之后,模型不需要合成判定也能判对。
这与之前的预判一致——**判定层在"证据已经足够明确"的场景里是冗余的**。

【推断】判定层可能在**证据模糊**的场景才有增量:L1 给出的是原始信号(状态码、失败列表),
模型要自己判断"这算不算失败";当信号是 202/静默失败/后台轮询干扰时,自判可能出错。
**这需要新场景验证,本探针没有覆盖。**

## 必须说清的边界(H0)

| 限制 | 说明 |
|---|---|
| 单轮单模型 | 每档 1 次,只有 kimi-k2.7-code;**无统计显著性** |
| 单场景 | 只有"前端乐观 UI + 后端 422"这一种失败模式 |
| 强信号场景 | 422 对模型是很好读的信号;弱信号场景未测 |
| 弱模型假设未验证 | kimi-k2.7 在这题上表现不弱,可能压低了 L1→L2 的差值 |

**结论:不能说"判定层没用",只能说"在这个强信号场景、这个模型上,判定层没有额外贡献"。**
这正是 H0 该产出的东西——它验证了消融开关有效,并暴露出 C1 正式实验需要补的场景。

## 下一步(正式 C1 需要)

1. **加弱信号场景**:202 后异步失败、静默失败(4xx 但 DOM 无变化)、后台轮询 2xx 干扰。
   这些场景里 L1 的原始证据"看着像成功",模型自判可能出错——**这才是判定层的用武之地**。
2. **多轮重复**:每档 ≥5 次,记录方差。
3. **多档模型**:至少一个明显更弱的模型(验证"判定层对弱模型更值钱"的假设)。
4. **A6 五反例全跑**:目前只覆盖反例①。
