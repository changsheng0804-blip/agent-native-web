# 项目治理与维护规则

## 权威入口

【已确认】唯一远程主仓库为 [agent-native-web](https://github.com/changsheng0804-blip/agent-native-web)，默认分支为 `master`。旧地址 `agent-web-suite` 会重定向到该仓库，并不是另一个独立项目。

活动源码为 `mcp/`、扩展清单声明的源码、`tests/fixtures/` 和 `skills/agent-world/`。开发和验收在含本文件的仓库根目录执行，开始前用 `git rev-parse --show-toplevel` 和 `git remote -v` 核对位置。

【已确认】本次复查时，外层工作区保留了旧 Git 检出和未入库历史材料，活动仓库位于同名工作区的 `agent-native-web` 子目录。外层只作为历史资料入口。工作区导航文件记录具体路径，历史材料不自动发布到远程。

## 工程验收与协作

- 每项变更一个任务分支，命名与提交追溯见[贡献约定](../CONTRIBUTING.md)。
- 所有合并经过 PR（合并申请）；“工程验收”是必需的自动检查，分支必须跟上最新主线，讨论必须解决。
- 单人维护暂不要求外部审核人批准；仍由维护者检查变更目的、验证证据和遗留事项。
- 使用压缩合并，远端自动清理已合并分支。未合并实验先建立 `archive/` 标签（保留提交的历史标记），核对提交编号后再清理分支。
- 不重写主线历史，不把历史分支的独有提交当作已验收功能直接合入。
- 自动验收包括依赖锁定、有效文档链接、测试登记、模块依赖方向、扩展源文件一致性、Python 正确性与完整离线测试；在 Python 3.10 和 3.12 上执行。
- 报告保留 14 天作为 GitHub 运行附件；长期有意义的结论才写入 `docs/`。本机运行证据位于 `.治理证据-evidence/`，不提交登录态、截图缓存或原始用户数据。

【建议】依赖变更时重建锁定清单并跑完整验收；每次合并前核对主分支规则，每月人工复查标签、实验分支、文档索引和待决事项。不设置无人值守定时任务。

## 代码与测试边界

【已确认】根 README 的测试数量由工程检查核对。`mcp/experiments/test_time_aware_engine.py` 是独立实验引擎测试，`mcp/experiments/test_server_evidence.py` 包含 GitHub 真站动作；这两项保留为明确分类的人工实验入口，未纳入离线必需门禁。

【已确认】扩展中 `runtime/`、`overlay/`、`ui/`、`popup/` 和根 `content.js` 是未被当前清单加载的旧原型。用途与支持范围见[扩展说明](../extension/README.md)。保留目录不等于已完成产品验收。

【不确定】离线门禁不能证明真实网站登录、反爬、多账号权限或所有浏览器版本兼容；只能按具体站点、动作与环境提供单独证据。

## 版本与发布

【已确认】`pyproject.toml` 的 `0.1.0` 是项目实验版本；扩展与网页接口的 `1.0.0` 是内核版本，属于不同对象。现阶段以 Git 提交编号定位可复现版本，没有正式软件包或浏览器商店发布。

【建议】正式发布前由维护者确定统一的发布清单：许可、版本、变更说明、目标平台、支持范围、完整门禁和至少一个获授权的真实场景验证。归档标签不是产品发行版，不为完成治理虚构发行记录。

## 方向判据与冻结（2026-09-08）

【已确认】方向判据以[核心命题-反馈闭环是第一杠杆](核心命题-反馈闭环是第一杠杆.md)为准：

```text
感知层（编号/导览/地图/截图/DOM/a11y）  →  可替换的传感器，不做护城河
证据 / 因果 / 验证 / 信任 / 恢复          →  核心 Runtime，长期价值所在
```

【已确认】边界表述（不得简化为"验证不会被模型吃掉"）：**验证中需要「缺失的外部证据、权威状态、因果关系和来源身份」的部分，不可能靠单纯模型 scaling 凭空解决**；但验证层内"从已有观察做更准判断"的部分仍会被模型能力改善。这是 observability/evidence 问题，不是 intelligence 问题。

【已确认】以下对象**冻结**（保留代码与追溯，不再投入，不接受新功能）：

| 对象 | 依据 |
| --- | --- |
| 任务运行时图 / 业务运行时 / 站点适配器 | A/B 实测无提速（66.9s → 70.0s，慢 4.6%），见[A/B 对照基准](archive/A-B对照基准%20GitHub.md) |
| 地图公地（跨用户共享） | 项目自判"过期先验危害 > 没有先验"，见[已归档方向文档](archive/探索方向-地图公地与小票标准.md) |
| 4 篇「探索方向」文档 | 结论已提炼进核心命题与落地路径，已归档至 `docs/archive/` |

【建议】冻结不等于删除：代码保留，但新功能不进入；如需解冻，必须先给出可证伪的判据与实测结果。
