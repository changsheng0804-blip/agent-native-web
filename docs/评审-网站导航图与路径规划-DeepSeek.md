## 0. 评审结论（一句话）

**方向成立、工程上最成熟，值得做"合并版阶段 0 最小验证"；但它的天花板是"省调用、降方差"，不是"省时间"；从"值得验证"升级为"值得建设"的门槛不是技术实验，而是一份目前缺失的任务侧重复度数据。**

| 项 | 结论 |

## 1. 价值分析（三层）

### 1.1 对使用者的价值

- **省探索调用**：第二次走同路径时跳过 guide/部分 find/失败重试。按 E3 基线（18 调用/轮）估算，探索类调用约半数，理论节省上限 **4-6 次调用/轮**。
- **几乎不省墙钟时间**：E3 实测 open 占 57.8s/65s ≈ **89%**（见 §0 修正说明），时间节省上限约 11%（~7s）。
- **省的是方差，不只是均值**：已知路径 + 每步校验的执行方差远小于现场探索。对"包工头+监理"叙事，**可预期的成本报价本身就是价值**——现场探索波动（8 次 vs 20 次调用）是调度方无法预算的，先验把波动压下来。这一点原文档未提，是本评审补充的主要价值来源之一。

### 1.2 对项目的价值

- **只缺一块拼图**：fingerprint（认元素）、page_outcome（验结果）、world_map（单页结构）均已验证，缺的只是"持久化 + 跨页连接 + 查询"。
- **一鱼三吃**：阶段 0 实验同时产出 E1 数据、地形方向第二轮对照、导航图 H2——一次跑动喂饱三条验证线。
- **公地封存的自然收敛**：不赌网络效应，单用户即有价值，ROI 判断基于当下而非未来。

### 1.3 战略价值（期权性质）

- WebMCP 普及后，图自动降级为"验证工具结果的参考先验 + 无门时兜底"，与双通道叙事兼容（对齐原文档开放问题 #4）。
- 若 E1/E2 数据将来有利，本地导航图即公地解封时的数据源。免费期权，**不计入当前 ROI**。

### 1.4 价值衰减曲线（必须正视）

方向价值与模型能力负相关：更强模型 + SoM 视觉使现场探索变便宜、变可靠，先验相对价值被持续侵蚀。对冲因素：任务越深（≥3 层、状态复杂），现场探索成本非线性上升，先验相对价值上升。
**时间窗：验证工作在 2-4 个季度内完成，否则价值被模型进步吃掉。建议作为方向级停止条件之一写进文档。**

## 2. ROI 分析（分阶段）

| 阶段 | 成本（人天） | 收益 | ROI |
|---|---|---|---|
| 阶段 0 最小验证（合并 E1/地形第二轮/SPA 站） | 1-2 | 三份决定性数据 | **极高，无脑做** |
| 阶段 1 被动积累（T0 指纹落盘 + act 记录钩子） | 3-5 | 路径复用真实覆盖率与命中 | 中低，成败取决于阶段 0 |
| 阶段 2 world_path + 探针降级 | 3-5 | 复用收益兑现 | 低-中，收益被探针成本分走 |
| 阶段 3 语义推断 | 2-3 | 与 prompt 级等价 | **低，砍掉** |

关键算账：一次复用净省 ~4 次调用（扣除探针后可能仅 2-3 次）；构建+维护约 10-15 人天。**盈亏平衡 ≈ 数百次实际复用。**

### 2.1 最大 ROI 变量：谁在重复走同一张图（当前缺口数据）

- 目标市场是长尾站点（WebMCP 未覆盖）——恰恰是低频访问（半年一次），重复度≈0。
- 重复度高的场景（SaaS 后台、监控、比价）要么有 API/WebMCP，要么不是长尾。
- 原文档 H2 自问"N 是多少"，但未追问：**有 N 次复用需求的人是谁、占任务总量多少？**
- 阶段 0 只能测"复用能省多少"，测不出"多少人需要复用"。后者需任务侧画像：从真实站测试日志统计同站同路径重复出现次数分布（成本约半天）。

## 3. E3 数据引用修正（原文档硬伤）

原文档 §十.H1 写"open 占总时间 57.8%"；E3 原始记录（`探索方向-地图公地与小票标准.md` v2 §3）为 **"总时间 65s·轮（open 占 57.8s）"——57.8 是秒，open 占比 ≈ 89%（近九成）**，不是 57.8%。

修正后影响：H1 的"省时间"叙事不成立；价值重心必须从"时间"移到"调用次数 + 恢复次数"（对齐合作复盘确立的价值度量）。

**主指标修正建议：主指标 = 工具调用次数 + 错误恢复次数；时间仅作次指标。原文档 Step 4 的"调用次数和时间显著低于"需明确主次，否则验证通过也会误导后续判断。**

## 4. 难点清单（完整分级）

### 4.1 原文档已识别

| 难点 | 严重度 | 影响 | 缓解 |
|---|---|---|---|
| 节点身份（SPA 下 URL 失效） | ★★★★ | schema 前提，未解 | 阶段 0 顺手测"URL pattern + 首屏关键元素指纹"组合 |
| 指纹命中率复利（多步路径贴近停止线） | ★★★ | 收益上限被数学锁死 | 接受"概率性温和节省"预期，用 E[节省] 期望值定价 |
| 探针成本吃节省 | ★★ | 收益再腰斩 | 探针与探索调用分开记账 |
| 过期先验危害（E2 待测） | ★★★★ | 7.2 设计合理但探针兜底能力未实测 | E2 解封判定作为阶段 1 前置门 |

### 4.2 本评审补充（原文档未展开）

1. **覆盖率不可测量（GPS 类比陷阱）**：被动积累图只含"走过的路"，永远不知"没走过的路"有多少，无法回答"图何时够用"。GPS 路网是有人测绘过的完整先验，被动积累图不是——该类比实际削弱而非支持 H2。缓解：阶段 1 加"同站另选一个未走过任务，测图中率"对照。
2. **指纹撞车 = 静默误导**：真站指纹撞车率 6-11（`docs/验证方案-实时闭环.md`），边锚在撞车指纹上会指错方向且无告警。图写入端必须做撞车拒绝，节点/边结构需加此字段。
3. **同 URL 多状态**：分页、筛选、tab 切换下 URL pattern 相同而语义不同；静态站也存在，不仅是 SPA 问题。节点身份方案必须覆盖。
4. **多边竞争的分辨率**：同 from→to 可能多条边（多个按钮通向同一目标）。v0 建议直接选"细粒度 + 失败即降级"，不做合并。
5. **测试体系成本**：无法本地夹具完全模拟（A/B 测试、动态过期只能真站复现），real 组用例拖慢流水线。策略：图相关测试进 real 组但允许 SKIP 容错。
6. **API 边界（原文档遗漏）**：world_guide 已是单页任务导览，world_path 是跨页版，职责重叠。**建议跨页路径整合进 guide 的返回（带 world_epoch 失效语义），不新增工具**，避免破坏 6 词协议与 SKILL 层。此决策须在阶段 2 之前定。

### 4.3 非目标与边界（写死，防止蔓延）

- 表单提交类路径 v0 不进图（前置状态不可知，开放问题 #5 高危区；与"后果卡诚实"价值观一致）。
- 不跨用户共享、不建平台、不处理隐私画像问题（本地文件级）。

## 5. 决策门（给后续智能体进程的硬门槛）

### 阶段 1 立项门（三条缺一不可）

- [ ] D1：E1 数据显示同站二次进入净省 ≥ 3 次调用/轮（含探针成本，分开记账）；
- [ ] D2：任务侧重复度画像显示同站同路径重复占实际任务流有体量（非感觉，用日志统计）；
- [ ] D3：E2 解封判定不否掉"探针兜底"机制（过期先验危害率可控且可低代价恢复）。

### 阶段 2 立项门

- [ ] D4：节点身份方案落地（含同 URL 多状态覆盖）；
- [ ] D5：探针记账后 E[节省] > 0；
- [ ] D6：路径全命中概率 ≥ 70%（含指纹命中 × 后果卡正确的双重条件）。

### 方向级停止条件（新增）

- 模型进步导致现场探索成本低于复用成本（时间窗 2-4 季度）；或
- 原文档 §十二 停止条件任一条触发。
