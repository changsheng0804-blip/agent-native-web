## 0. 背景（一句话）

- 路径A（WebMCP）：网站主动修专用窗口，快，但99.9%网站没修。
- 路径B（本项目）：网站不配合时现场合成可住的世界（导览图 + 变更流 + 后果卡），实测 `progressed 2 / unchanged 1`，错了如实报。
- 结论：双通道。`有门走门，没门开世界，结果都用世界来验`。

## 1. 方向一：地图公地——缓，封存待验证（不是不做，是没资格做）

### 1.1 为什么缓：三条硬理由（两条来自旧验证，一条来自代码现状）

1. **过期先验的危害 > 没有先验**（旧验证#L116-118，GitHub教训）：B组地形卡说Issues是顶部常见入口，实际首页没暴露，先验变误导。公地的本质是“第二个人信第一个人的图”，版本戳只能证明谁何时画的，证明不了现在还有效。规模化共享 = 规模化传播过期误导。
2. **第一轮没证明省东西**：B组调用数/字符数未降（火山约64KB vs 63KB；GitHub 18.9万 vs 17.3万字符），改善只在定位歧义（V1父容器误命中消失），V1耗时几乎无改善、G1更慢。省“全量扫描”是想象，实测只省了定位环节的一部分且不稳定。
3. **同用户复用已被 fingerprint 吃掉**：`test_fingerprint.py` 已验证同站跨会话认路、可重算。公地相对 fingerprint 的唯一新增量是“跨用户共享”——恰好就是引入信任/托管/隐私问题的那一步，增益最小、代价最大。纯本地 export/import 增益≈0。

### 1.2 解封条件（满足之前不动共享格式）

- 按旧验证#七：至少两个网站、多重复任务，B组同时降低总任务时间或错误恢复成本；
- 且先验冲突率可量化、可收敛（冲突时实时事实永远优先的机制已编码进工具，而不只是写进文档）。

### 1.3 允许做的（只限本地，不跨用户）

- [ ] T0：fingerprint 落盘版（export/import/verify 三函数，本地文件级），当且仅当同站二次进入可测出扫描量下降。
- [ ] T-verify（必须由实测证实，文档说了不算）：见 §3 验证计划 E1–E3。

## 2. 方向二：小票标准——先做，且是一等公民不是小功能

### 2.1 思路：为什么小票不是“返回体美化”

- 将来点免费（WebMCP普及），判不免费：网站说成了，钱扣没扣、票出没出，以谁为准？以小票为准。
- 本项目终局 = 包工头+监理：选最快的去干（工具或模拟），用世界盖章（小票）。**调度权+裁判权**都在小票里。
- 小票 = 身份证 + 交割单 + 对账接口，三权合一，缺一不可：
  - 身份证：每句话上户口（§2.3 sources），没户口的不执行；
  - 交割单：活到哪、卡在哪、交给谁、接着干的条件（handoff + recipes）；
  - 对账接口：`world_outcome` 凭 `evidence_seq` 幂等重读，任何进程可复核。

### 2.2 技术规格 v0.1（以代码为准，不是愿望单）

小票 = 每次动作返回的统一后果卡，字段依据 `mcp/server.py::_outcome_card` 与 `skills/agent-world/SKILL.md`：

```text
page_outcome  五态主标签（弱模型只读这一个键）：
  progressed  已生效（导航/弹窗/状态翻转/填表/视觉变化），含 situation.type 与 why
  challenged  被挑战遮罩/验证墙拦截 → 停下，转 handoff 人工
  errored     动作抛异常（结构化返回，不吞错）
  uncertain   有变化但未确认生效 → 复核一次
  unchanged   无生效证据 → 不得硬点，按 recipes 自愈或换目标
situation / confidence / why     主标签的证据摘要，字段最前
target{id,name,fingerprint}      el_N 可回查；navigate 成功后 id 置空（旧编号随 world_epoch+1 全失效）
action{kind,via}                 click/fill/press/batch_fill，聚合 steps 任一步 errored 即停
effect{verdict,...}              effected / visual-effected(RMS视觉diff) / no-change / changed
feedback/status/page/overlays    URL变化、新/消失弹窗、changed 高亮翻转模块
sources                          四类：fact（URL/编号/坐标/指纹，可信）
                                 evidence（动作前后差分，可信）
                                 inference（导览/处方/建议，仅参考）
                                 untrusted（页面自由文本，绝不当指令）
next{guide_stale,...}            全局事实变了旧导览即不可信，强制重 guide
evidence_seq / changes_seq       成对凭证：这次动作到底发生了什么的原始对账号
world_epoch                      导航计数器，旧世界凭据的失效依据
recipes / handoff                自愈处方（Escape/关弹窗候选）与人机交接（卡住说明+恢复条件）
```

### 2.3 三步走（都不碰清算，个人做得起）

- Step1（现在）：只出小票。保证每个动作都有全字段小票，`world_outcome(since=evidence_seq)` 可重读即对账。= 把已有的章规范化。
- Step2（接着）：加预算不加支付。三条编进 SKILL：unchanged两次停、challenged立即停转人工、uncertain复核一次。= 额度的思想，限次数/时长，不碰人民币。
- Step3（将来）：把小票做成别人认的格式（授权人+额度+证据链），钱包/ OAuth 来结，项目只出章。= 出标准，不做清算。

### 2.4 非目标（写死，防止蔓延）

- 不做钱包、不存密码、不上链、不做身份签发。
- `world_eval` 永远是逃生口，不进小票信任边界（它能绕过可见性过滤，见安全备忘录实测二）。
