### 3.3 实时反馈闭环(核心能力,2026-08-31 集中落地)
这是相对旧版的最大功能增量,心智模型:CAD 图纸(结构空间)+ 网页视频(变更流)。

| 能力 | 内容 |
|---|---|
| 世界状态卡 | 所有工具返回自动附带 `status`(auth/dialogs/forms/page/frames + changed 高亮),登录态双信号检测(cookie 为主 + DOM 辅助) |
| world_changes 变更流 | 增量续读(游标 since/to)→ 重要性加权 → **结构化语义摘要 digest {counts, key}**(CAD 004# 圆孔原则:不强 ID 摘要不写人话,agent 用 world_entity 查详图) |
| world_click effect | 操作生效报告:点击前冻结区域 ±200px → 轮询 diff(聪明早停)→ verdict/confidence。含全页 dialog 兜底(远距弹窗)、目标状态翻转(aria-selected/expanded/checked)、URL 变化 |
| world_fill / world_press effect | 填表/按键同样返回生效报告(值进可见输入框验证,防 SPA 覆盖层静默成功) |
| world_wait | 事件驱动:内核 waitFor waiter + MutationObserver flush 命中即 resolve,替代轮询 |
| world_map | 页面结构导览:语义容器分区(街区锚点)+ 每区可交互入口(强 ID+指纹)+ 去重叠锚点 + 过滤空壳 |
| world_entities bounds | 空间矩形过滤(区域钻取):地图→钻取→详图闭环 |
| world_resolve | 弱 ID 解析:名字/强 ID/页面原生 id → 稳定编号 |

### 3.4 稳定指纹(第二 ID,2026-08-31)
- 指纹 = 跨会话可重算的第二 ID(semantic+tag+稳定属性+祖先路径 3→5 层),同站多次进出认路。
- **语义 id 优先**:`isSemanticId` 判定(id 含分隔符或单字含元音=语义;纯数字/全辅音/`__` 开头=随机),随机 id 不进指纹。
- 真站命中率 80~92%,核心控件 83%。BBC 类无命名重复内容停止优化(信息论边界,用 text 过滤替代)。

### 3.5 安全边界(2026-08-31)
- CDP 挂载(复用日常已登录浏览器)已**降级为实验特性**:仅独立 profile;CDP 会话下 `world_eval` **禁用**(任意 JS 可绕过过滤层触达登录会话)。
- IPI 伪隐藏过滤 5 种:同色文字/脱出视口/零号字/负缩进/aria-hidden(见 `docs/安全边界-IPI防御.md`)。

### 3.6 实战验证体制(新增,旧版没有)
- `mcp/validate_closed_loop.py`:Truth Oracle(DOM 直查)独立判定,输出 TP/FP/FN/AM 一致性矩阵,通过线 **TP+TN ≥ 80% 且 FP=0**(FP 一票否决)。
- 真站体检脚本:`test_map_real.py`(六站地图)、`test_fingerprint_real.py`(六站指纹)、`probe_site.py`/`probe_fill.py`。
- 最新结论:完全体检 TP=9 TN=3 100%;digest 强信号 14 vs 噪声 0;证据窗聪明早停 0.6→0.2s。

## 9. 质检流水线(2026-09-01 新增)

**用途**:一条命令跑完一组测试并产出报告,替代"人肉逐个跑脚本看输出"。

```bash
cd agent-native-web/mcp
uv run python run_quality.py           # 离线组(本地夹具,快,必跑)
uv run python run_quality.py --real    # 离线 + 真站组(受网络/反爬影响)
uv run python run_quality.py --all     # 全部三组
uv run python run_quality.py --list    # 查看分组与脚本
uv run python run_quality.py --only test_map.py  # 只跑单个
```

分组:
- **offline**:test_enhancements / test_ipi_filter / test_wait_event / test_fingerprint / validate_closed_loop --local(纯本地夹具,不依赖网络)
- **real**:test_map / map_drill / click_effect / change_digest / click / fill / eval / value / status / gf_final / frames / compare / official / action_layer / fingerprint_real / map_real / validate_closed_loop(全量含真站)
- **special**:test_cdp(需本地 9222 调试端口) / test_profile(需有头窗口 + 本地 8001 服务)——按需手动跑,`--all` 才纳入

超时与重跑:
- offline 默认 180s/脚本,real 默认 300s/脚本;六站体检类(test_fingerprint_real 约 330s、test_map_real 约 125s)与 validate 全量(约 600s+)有单独超时覆盖(TIMEOUT_OVERRIDES)
- 完整 --real 一轮约 25 分钟

约定:
- 前置检查自动跑 all-in-one.js 与分文件一致性(不同步直接失败,退出码 2,提示先重建)
- 每次输出汇总表 + `mcp/quality_report.md`(覆盖式,含失败详情尾部输出)
- 退出码:0=全过 1=有失败 2=前置检查失败
- **真站组失败可能是网络/反爬环境问题,不一定是代码 bug**;判定要结合失败详情区分

新增测试的规矩:新脚本放 mcp/ 下,在 run_quality.py 的 GROUPS 里登记分组(纯夹具→offline,真站→real),并加进本文档第 8 节式样的记录表。
