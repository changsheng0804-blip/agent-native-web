# LLM 试验台试点记录(方法验证)

- 日期:2026-09-19
- 目的:验证「子代理即被试」的基准方法(零外部 API 成本),为真模型复跑两个标题数字(假成功 X%→0%、注入减半)铺路
- 被试模型:GLM-5.3(经 DimAgent 子代理;每次试验新鲜会话,零项目上下文,提示词不透露任何故障设计)
- 载具:`llm_trial_rig.py`(每试验自包含:页面服务器 + 故障注入 + MCP 会话 + commands/ground_truth 审计日志)

## 设计

- 双臂,**提示词逐字相同**,唯一实验变量 = `click` 命令返回的内容:
  - `ui` 臂:仅回 `(clicked)`,页面观察仅 `read`(body.innerText)
  - `receipt` 臂:返回后果卡关键字段(page_outcome/situation/why/errors)
- 动作机制两臂完全一致(world_find → world_act),差异只在信息返回
- 判分:服务端真值(422) vs 代理最终 `RESULT:` 行;commands.log 同时留痕真实 page_outcome
- 页面:`tests/fixtures/llm_trial_register.html`(中性注册页,可见文本零剧透)

## 第一轮(作废)与教训

沿用 `external_facts.html` 作为对照页——其**可见文本自带**「XHR 实际返回 422」的说明。UI 臂 3/3
全部靠"读页面说明书"答对(receipt 臂 3/3 靠后果卡答对,机制正确但样本无效)。试验台当场暴露了
这一效度威胁;其中一个 UI 臂代理还在结论里主动标注"我的判断完全依赖页面内置说明,脱离它无法区分"。

**教训:对照页必须是不自我剧透的中性任务页。**

## 第二轮(中性页,n=3/臂)

| 臂 | 判对 | 明细 |
|---|---|---|
| receipt | **3/3** | 全部引用 422/email_taken 证据作答;其中一个还重复点击验证可复现性 |
| ui | **1/3** | 2 个判 `SUCCESS`(理由均为「页面状态变 ✅ 且稳定无报错」——典型系统性乐观偏差);1 个判对,但依据是「空字段被接受 + 重复提交无差异化反馈」的怀疑推理,**并非观察到后端事实** |

## 已知局限(诚实清单)

1. n=3、单模型;方向与 720 次脚本基准一致,但无统计显著性(3/3 vs 1/3,Fisher p≈0.4)。
2. `read` 信道 = body.innerText,输入框 value 不可见——ui-1 的怀疑推理部分来自该信道伪影;
   正式版 `read` 应附带表单值摘要。
3. 代理理论上可绕过 CLI(自行发起 HTTP);本轮未见,正式版需协议收紧 + 留痕核对。
4. 未测 token(子代理上下文外部不可读);正式指标以动作数/步数/耗时为主。
5. 单场景(422);rollback / 202 异步 / 账本臂待扩展。
