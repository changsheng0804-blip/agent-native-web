## 结论(可证部分)

1. **挑战检测(9 夹具)**:形状启发式 **P=0.50 R=0.20 F1=0.29**;Jev 语义臂
   **9/9 全对(P=R=F1=1.00),且阈值 0.3~0.9 全区间稳定**(正例 0.90~0.98,负例 0.03~0.06,间隔极大)。
2. **IPI 文本(44 条)**:正则基线 **R=0.50**(22 条注入漏 11 条,另误报 1 条);
   Jev 阈值 0.6~0.8 时 **P=0.96 R=1.00 F1=0.98**;阈值 0.9 时 P=1.00 R=0.95(仅 pos07 落到 0.84)。
3. **关键设计发现(v1→v2)**:Jev 语义臂依赖"**同源 iframe 文本入 state**"。
   v1 中 p1/p5 因挑战文本在 iframe 内部而漏判(0.37/0.19);把同源 iframe 文本加入 state 后
   变为 0.96/0.90。**你们的运行时状态卡已有 frames 逐层遍历,该能力现成**——接入时不要漏喂。
4. **两臂盲区互补**:形状规则抓"全屏+iframe"但漏 4 类变体(无 iframe/小浮层/非 fixed/内联文本),
   且对合法 iframe 浮层误报(n2 支付浮层);Jev 抓语义但依赖文本可见性(跨域 iframe 不可读)。
   组合建议见 §5。

## 生产口径三对比(第三轮:接入路径验证)

同一批 9 夹具,三种 state 口径喂 Jev(口径定义见 `run_bench.py` docstring;
`prod` 口径刻意不传 situation.type / page_outcome,防泄漏启发式答案):

| 口径 | 正确率 | P | R | F1 | 说明 |
|---|---|---|---|---|---|
| `script`(v2 自建 JS) | 9/9 | 1.00 | 1.00 | 1.00 | 主文档全文+浮层几何+同源 frame 文本(基线) |
| `prod`(现状运行时输出面) | 7/9 | 1.00 | 0.60 | 0.75 | 回执几何事实 + 构件文本面 + world_state 信号 |
| `prod_frame`(prod+同源 frame 文本) | **9/9** | **1.00** | **1.00** | **1.00** | 阈值 0.3~0.7 全稳(0.8 起 p5=0.78 掉出) |

对照:形状启发式 4/9(P=0.50 R=0.20)。

**三个发现:**

1. **现状输出面已到 7/9**:主文档的验证文本会进入世界模型构件面
   (`world_entities` 的 name/text,如 p4 的 `content.请完成人机验证以继续-…`);
   负例全对(含 n2 支付浮层 0.12)。**接入不需要为"文本"另建通道——构件面就是现成文本通道。**
2. **唯一缺口是 iframe 内文本**(prod 口径下 p1=0.15 / p5=0.07):挑战内容在 iframe 里时,
   父文档构件面为空(`content.unnamed`)。补一条同源 frame 文本后 → 0.94 / 0.78,9/9。
   运行时状态卡的 `frames` 遍历已是 server 层 `f.evaluate`(CDP 级、跨域可读),
   **加一个 text 字段是一行级增量**;或经现有 `world_eval` 一条表达式取同源 frame 文本。
3. **p5 是阈值敏感点**(0.78):其信号较弱(iframe 内"滑动以完成验证"+ absolute 非 fixed 定位)。
   采用 0.8 以上高阈值会漏掉它;0.3~0.7 全区间安全。

**样本(prod_frame / p1 实际喂给 Jev 的 state 摘录)**:

```text
- 新出现 fixed 全屏遮罩(约 1440x900px)内含 iframe(400x450px)
- iframe 来源: (同源/空白)
- 页面状态: stable
- iframe 内可见文本(同源可读): 请完成验证以继续 我不是机器人
页面文本面(构件名/文本,截断):
- heading.创建账号 | 创建账号
- button.提交 | 提交
...
```

**附带观察**:构件文本面里 `root.html`/`root.body` 会带出 CSS/JS 源码噪声(截断内无害),
接入时可考虑对根元素文本裁剪——工程细节,不影响判定。

## 诚实局限(必读)

1. **n 小且夹具为合成**:挑战 9 例、IPI 44 条,均非外部基准;结论是"零件合格"级,不是通用性能声明。
2. **单模型版本、单次运行**:无重复采样方差测量;v1/v2 漂移数据仅作粗略参考。
3. **Jev 臂 state 由本实验脚本拼装**(可见文本+浮层/iframe 几何+同源 iframe 文本),
   与生产运行时的拼装口径尚未对齐——接入前应统一口径重跑。
4. **跨域 iframe 文本不可读**(真实 Arkose/hCaptcha 类),该类仍依赖形状信号;组合设计见 §5。
5. **阈值结论仅对本夹具集成立**。换域需重校——搜狐实测的教训(失分集中在阈值附近)
   在本实验 Part B 的 neg04/neg18(0.5~0.9 边界带)同样可见。
6. 延迟/成本数据来自本机网络与单次运行,不代表部署环境。

## 对接入的直接建议

1. **challenged 检测**:以 Jev 语义分类为主判(建议阈值 **0.3~0.7**,见 p5 敏感性);
   state = 回执几何事实 + 世界模型构件文本面 + **同源 frame 文本**
   (最小增量:状态卡 frames 遍历加 text 字段,或 world_eval 一条表达式)。
   第三轮实测:该口径 **9/9**;不补 frame 文本则 7/9(漏 iframe 内容类)。
   形状规则可降级为不确定带的次级信号(v1 数据:该组合 8/9)。
2. **IPI 逐块分类**:可用,建议阈值 0.6~0.8;判定输出只进 `inference` 源
   (不改变 sources 纪律,不授予指令执行权)。
3. **下一步**:接生产运行时口径重跑(统一 state 拼装)+ 在自有夹具集上校准阈值;
   之后再进"反射臂 × 窗口轴"主实验(见对话中记录的主实验设计)。
