# 主实验报告:反射臂 × 翻脸窗口轴

- 日期:2026-09-21
- 模型:`typesafe/jev-1.13`(经 OpenRouter `/api/alpha/decisions`)
- 数据:`reflex_results.jsonl`(120 次运行,20 格 × n=6,零崩溃)+ `validation_results.jsonl`(容错修复后复验 9 次)
- 复现:`uv run --directory agent-native-web python mcp/experiments/e2e_target/run_e2e.py --reflex --runs 6`
  (汇总 `--reflex-summary`;需要 `OPENROUTER_API_KEY`)

## 一句话结论

**单次读取的页面观察,正确性完全取决于"翻脸窗口"是否落在读取时刻之前**——窗口 10s 时
18/18 全错(12 次假成功 + 6 次漏报);**连续观察 + Jev 分类的反射臂在全部窗口下 62/63 全对**
(主实验 53/54,1 例为初版容错缺陷;修复后复验 9/9),失败检出延迟中位数 **0.93s**。

## 实验设计

- **臂**:
  - `ui`(对照,既有策略):提交一次 → 固定 5s 后读一次页面 → 按文本声明;
  - `reflex`(新):提交一次 → 每 0.8s 读页面文本,变化即交 Jev 分类
    (成功终态 / 失败终态 / 进行中);失败终态**立即上报**;成功终态保持到**观察预算(13s)**结束才声明。
- **窗口轴**:翻脸延迟 ∈ {1s, 3s, 10s}(覆盖任务的 `rollback_after_ms` / `delay_ms`;
  回滚概率固定为 100%——原 s1 为 40% 概率,本实验让翻脸确定性发生,窗口成为唯一变量)。
- **格子**:s1(回滚→已取消)/ c2(驳回→已驳回)/ s2(延迟→已确认)× 3 窗口 × 2 臂 = 18 格 × n=6;
  另加 s3(页面撒谎,无窗口)2 格 × n=6 作边界格。
- **判分**:只用账本(既有 `check_success`);**打分等待与窗口对齐**(打分发生在翻脸窗口 +2.5s 之后,
  否则长窗口会把"尚未翻脸"误记成终态——本轮为此修正了 harness 的打分等待,这是长窗口实验的必要前提)。
- 口径:假成功 = 声明成功 ∧ 账本非成功;漏报 = 声明失败 ∧ 账本成功。

| 格 | ui 成功率 | ui 失败形态 | reflex 成功率 | reflex 失败形态 |
|---|---|---|---|---|
| s1/w1000 | 100% | - | 83%(5/6) | 1 例假成功(初版容错缺陷,已修复) |
| s1/w3000 | 100% | - | 100% | - |
| **s1/w10000** | **0%** | **假成功 6/6** | **100%** | - |
| c2/w1000 | 100% | - | 100% | - |
| c2/w3000 | 100% | - | 100% | - |
| **c2/w10000** | **0%** | **假成功 6/6** | **100%** | - |
| s2/w1000 | 100% | - | 100% | - |
| s2/w3000 | 100% | - | 100% | - |
| **s2/w10000** | **0%** | **漏报 6/6** | **100%** | - |

- ui 臂:窗口 ≤3s 时 36/36 全对;**窗口 10s 时 18/18 全错**。
- reflex 臂:窗口格 53/54;修复后复验 9/9(s1/w1000 6/6、s2/w10000 3/3,无回归)。

## 三个结论(可证部分)

1. **单次读取 = 时序运气(已量化)**。窗口 10s 时,ui 臂 5s 读到的是"已确认/已通过"——回滚**尚未发生**,
   于是如实汇报"成功",而账本 10s 后翻脸 → 12/12 假成功;s2 则读到"处理中"就判失败 → 6/6 漏报。
   这与既有 720 次基准与 LLM 试验的边界说明("翻脸窗口更长时 UI 臂假成功会回来")完全一致,
   本轮第一次把它变成带对照的数据。
2. **反射臂与窗口无关**。失败检出延迟(n=35):**中位数 0.93s、P90 3.1s、最大 7.5s**
   (长尾来自 Jev API 延迟抖动,见 §5);在 w1000/w3000 下平均 2.0~4.0s 即宣布失败,
   比 ui 的固定 5s **更快且不依赖窗口**;w10000 下在翻脸后 ~1s 内上报,ui 则已假成功。
3. **边界:反射臂不解决"页面撒谎"**。s3(lie422)下两臂均 6/6 假成功——页面从头到尾说假话时,
   只有账本通道能救(既有 720 次基准里 runtime/channel 臂 100%)。**反射层管"何时翻脸"(时序),
   账本层管"是否撒谎"(事实),互补而非替代。**

## 一个真实缺陷与修复(诚实记录)

初版反射臂把"读失败"静默当作"无变化"(`txt = last_text`)。s1/w1000 #5 出现一次慢读失败 +
越过预算(声明@23.4s、Jev 仅 1 次调用、走 `success@budget`)→ 假成功。
**修复**:读失败计数 + 立即重试;预算结束做终检;终检仍读不到则**保守判失败**(FP=0:宁可判失败,
不谎报成功);同时记录回退原因。复验:s1/w1000 6/6、s2/w10000 3/3。

## 成本与可靠性

- 反射臂每运行 **1~2 次 Jev 调用**(中位数 2),平均成本 **$0.00003/次运行**;60 次运行总计 $0.0018。
- **Jev 调用回退率 18/104 ≈ 17%**(网络/协议失败时回退到字符串匹配;含回退的运行结果未见异常)。
  这是必须记录的真实可靠性数据:**反射层必须有降级路径**(本实现已有),且应记录回退原因(修复已加)。

## 诚实局限

1. n=6/格、单机、合成靶场(文本规则、无风控);Jev 的**泛化**优势由分类器实验(挑战检测 9/9、IPI F1 0.98)另证。
2. 检出延迟以"提交时刻 + 窗口"估算翻脸时刻,±0.3s 级误差(个别值 -0.05s 即此故)。
3. 观察预算(13s)必须 > 最大窗口;更大窗口需要更大预算——这是设计参数,不是缺陷。
4. s2 成功格:反射臂声明时刻 = 预算(13~17s),比 ui 的固定 5s 慢——"用观察预算换确定性"是刻意的保守设计,
   站点画像明确时可缩短。
5. 容错修复只复验了受影响格与一个成功格(9 次),未全量重跑(见 §4 说明)。

## 对接入的启示

1. **反射层设计参数**:轮询 0.8s;读失败立即重试 + 终检;预算 > 最大窗口;失败立即上报、
   成功保持到预算;终检失败保守判失败。
2. **判定**:Jev 的三分类(成功终态/失败终态/进行中)在本实验零误报,可直接采用;
   网络失败时回退字符串匹配(本靶场等效),真实站点需按分类器实验的阈值结论(0.3~0.7)处理不确定带。
3. **分工写死**:反射层(页面时序)+ 账本层(事实权威)+ 小票(逐动作后果)——三层合起来,
   "既快又不被骗"第一次有了端到端数据。
