## 结论(可证部分)

1. **P 策略 + 账本反馈臂 = 端到端零假成功**(240 次运行:runtime/P 与 channel/P 各 6 格 × 20,
   成功率 100%,谎报 0,重复 0)。结论卡的账本轮询 + 稳定检测(4s)完整继承 Phase 1 的
   "settled 检测"教训,端到端复现成立。
2. **Runtime 开/关的差距集中在"页面撒谎"这一类故障**:
   - s3(服务器谎报成功,账本无单):ui/P 谎报 20/20(100%),runtime/P 0/20
     (Fisher 单侧 p=7.25e-12)。纯 UI 观测(截图/OCR/页面文本)对此类故障**结构性不可见**。
   - 其余故障(回滚、慢响应、驳回)ui/P 恰好靠 5s 盲等"运气性通过"——这是本靶场
     参数下的结果,不代表 UI 臂的真实鲁棒性(见边界)。
3. **在途闸门在系统侧有效,在 agent 侧无效**:
   - s2(慢响应):ui/N 重复提交 20/20,闸门拦住后 runtime/N 重复 0/20(p=7.25e-12)。
   - 但盲策略被闸门拦住后不会等待/查证 → c1/c3/s2 的 runtime/N 全部**漏报成功**
     (declared=False,账本实际 confirmed/approved,20/20 每格)。闸门保护的是系统
     (不产生重复单),不是盲 agent 的任务完成率。
4. **盲策略(N)在所有故障格系统性失败**:总体成功率 ui/N 26%、channel/N 24%、
   runtime/N 11%;谎报率 39-42%;s1 的谎报率(35-55%)≈ 回滚注入率(40%),
   即"页面显示已确认就报成功"的盲策略对延迟回滚的失明率与故障率一致
   (s1 runtime/N 7/20 vs runtime/P 0/20,Fisher p=4.16e-3)。
5. **结论卡 ≈ 直接账本通道**:runtime/P 与 channel/P 在所有格表现相同
   (100%/0/0/0)。折中实现(后果卡,不让 agent 直接访问账本)在这组任务上没有损失。

## 实验设计

- 靶场:`mcp/experiments/e2e_target/`(多站点可插拔 + 服务器侧故障注入 + 幂等键账本
  + `/api/state`、`/api/verify?client_key=` 结构化闭环通道;禁止截图 OCR)。
- 站点:shop(列表→结算→订单详情 SSR)、content(发布→异步审核→通过/驳回)。
- 任务 6 格:shop/s1 回滚 40%@3s、shop/s2 慢响应 3.5s、shop/s3 谎报成功、
  content/c1 慢响应 3.5s(对照)、content/c2 驳回 100%@2.5s、content/c3 慢响应(只允许提交一次)。
- 臂:ui(仅页面文本)/ runtime(页面 + 后果卡 + 在途闸门)/ channel(world_eval 直查账本)。
- 策略:N 盲动(1s 无确认就回列表重开表单,同幂等键再提交,≤3 次)/
  P 稳判(提交一次,按臂的反馈等终态;runtime/channel 要求终态稳定 4s)。
- 判据只用账本:成功 = 声明 ∧ 账本终态 ∧ 提交次数;谎报 = 声明成功但账本非成功;
  重复 = 提交次数 > 1;漏报 = 声明失败但账本成功。每次运行独立种子,故障确定性注入。

## 与 Phase 0/1 的衔接

- Phase 0 证明:动态画布上观测层能无摩擦工作(304/304 归因,门控 10→1,回滚 20/20)。
- Phase 1(v2)证明:确定性 harness 中"结算优于盲等""A2 补丁不充分"两项被数据推翻,
  机制层只保留"闸门 + 通知 + settled 检测"。
- 本报告证明:把上述机制装进**真实浏览器 + 真实表单流程**(零 LLM、零 API key),
  端到端数字成立——账本反馈臂 240/240 零假成功;差距只在 UI 结构性撒谎的故障类上
  (s3),而这类故障恰好是"截图 OCR / 页面文本"永远看不到的。

## 边界与诚实性说明

1. **策略是确定性脚本**,不是 LLM agent。测的是**反馈通道的结构价值**(结论卡 vs
   页面文本),不是模型能力;对"真实 LLM agent 会更聪明/更笨"不做推断。
2. **s1 上 ui/P 的通过是时序运气**:5s 盲等恰好 > 3s 回滚窗口。若回滚窗口更长或
   UI 臂不固定等 5s,ui/P 会像 N 一样被回滚欺骗。不要把 s1 的 ui/P=100% 读作
   "UI 足以应对回滚"。
3. **延迟/回滚窗口是按需调参的**:N 的失败、P 的成功都在这些窗口内成立;真实站点
   延迟分布不同,但"盲重试产生重复单""页面撒谎对 UI 不可见"是定性结论,不依赖具体窗口。
4. 假成功口径:声明成功 ∧ 账本非成功。s2/c3 的 N 失败是"重复"而非"谎报"
   (账本确实成功了)——报告中已分开统计,与 Phase 1 的 fs_immediate/fs_deferred 口径一致。
5. c1 对照格允许重复提交(N 通过),它验证的是"管道本身能跑通",不是 N 的正确性。
